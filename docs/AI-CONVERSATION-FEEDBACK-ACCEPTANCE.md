# 文章 AI 统一会话反馈 · 本地验收（2026-08-30）

本文保留双按钮阶段的信息结构证据。后续入口已合并为一个“发送”，当前行为见 [统一发送验收](AI-UNIFIED-SEND-ACCEPTANCE.md)。

## 范围与结论

用户指出两处交互问题：快捷优化和优化页文字输入没有统一进入会话；修改说明与“待应用/已应用/未采用”状态容易被理解为互相替代。本次不改变 DeepSeek 协议、模型、请求次数或存储格式，只调整文章助手的信息结构。

现行行为如下：

- 点击常规优化或润色文笔后进入“和小文聊一聊”，生成过程和结果都留在会话；生成完成不会自动跳转全文预览。
- 优化页底部保留输入框外观，但它是“进入小文会话并输入需求”按钮；点击后进入会话并聚焦真正的输入框。
- 小文返回的 `answer` 显示为“小文的修改说明”；turn `status` 显示在回答气泡外的消息元信息区。应用和放弃只更新正文/状态，不覆盖说明；候选与原文一致时显示“无正文变化”，不再显示“待应用”。
- 每条候选在会话中提供“查看优化结果”或“查看调整结果”；预览返回、应用和放弃后均回到会话。
- 快捷优化和旧空 prompt 记录显示可读操作文字，不出现空白用户气泡。
- 从文章优化进入的会话关闭后先回优化菜单，未发送输入和进行中请求继续保留；优化菜单再次关闭才退出。直接“聊天”入口仍一次关闭退出。

## 浏览器回归

在内嵌浏览器复用本机测试文章及其历史候选，没有新建或删除用户作品，也没有产生模型请求。390×844 下，优化页仅显示可点击的会话入口；点击后进入会话并把焦点移至 `article-ai-question` textarea。已有候选同时显示：

- 小文的修改说明及原 `answer`；
- 独立的“未采用”状态与时间；
- “查看调整结果”操作。

用户随后指出状态夹在说明与结果按钮之间不合适。复核页面后将状态和时间移至白色回答气泡之外；在“AI 功能验收（测试文章）”中复用两个历史无变化候选，浏览器均显示“本次保留原文，未产生正文修改”与气泡外“无正文变化”，没有再次调用模型。

关闭导航增量在 390×844 复用同一测试文章验证：从优化菜单进入会话、输入未发送要求后，关闭按钮和 Escape 都返回“文章优化”；再次进入时输入仍在。优化菜单第二次关闭退出助手；从“聊天”直接进入时一次关闭退出且焦点恢复到“聊天引导”。自动化另用可控网络替身确认生成中返回菜单不会取消请求，完成结果仍出现在对话记录。浏览器没有发送模型请求。

## 边界

- 本次验证信息路由、持久状态和视觉层级，不评价新的模型生成质量，因此没有追加付费调用。
