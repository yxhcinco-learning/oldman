# 小文会话全流程梳理（2026-09-06）

范围：H5与小程序的正式代码、共享编排、请求上下文、界面及现有模拟器回归。不把假模型结果当成真实模型效果，不改用户作品。此次顶部与撤销布局已于 `86b831b` 本地提交。

## 一套会话，三个独立状态

不要再把访谈页面、请求状态和文章采用状态混为一谈：

| 状态 | 唯一来源 | 对界面的影响 |
| --- | --- | --- |
| 是否访谈 | `session.conversation.mode` | 访谈引导/普通回应；开启或结束文字操作 |
| 本轮请求 | turn 的 running/failed/cancelled/ready/answered | 三点等待、停止、错误重试或回复 |
| 文章是否采用 | turn、应用版本与当前正文 | 查看、采用、放弃、冲突核对、撤销 |

结束访谈不等于文章已生成；生成不等于采用；停止生成不等于恢复访谈；收起窗口不等于停止请求。撤销正文也不应撤销会话历史。

## 两条主线及交叉路径

| 场景 | 逻辑与数据 | 应有展示 | 当前核对 |
| --- | --- | --- | --- |
| 空正文普通交流 | 原始输入先保存，统一 dialogue；允许问候/讨论 | 连续消息，紧凑开启入口 | 共享及模拟器通过 |
| 普通交流提出改文 | 同次模型返回 edit，候选不直接写正文 | 回复内看看文章 → 独立预览 → 明确使用 | 应用/放弃/冲突已有回归 |
| 按钮开启访谈 | 本地写模式、系统事件和静态首问，无模型请求 | 顶部展开为访谈中与结束入口；保留已有消息 | 已覆盖；H5滚动依赖补修 |
| 自然语言开启 | 有效结构化 start 落库后切换；失败不猜测 | 不重复按钮开场，不解释两种模式 | 假transport覆盖，真实语义组合待补 |
| 访谈回答/问候/解释/反问 | reply 不退出；实质原话才关联材料 | 自然承接，每轮最多一个问题 | 结构覆盖；真实效果不能由假回复证明 |
| 改正素材 | 新素材关联原消息和被更正材料，旧记录保留 | 承认更正，不把旧事实继续当作有效事实 | 核心及模拟器覆盖 |
| 访谈中改正文 | 保存 pendingEdit，确认后 finish 合并一次生成 | 结束访谈并继续修改 / 继续访谈 | 主路径覆盖；确认后又聊别的边界未完善 |
| 按钮结束 | 先保存普通模式与事件，再整理 | 模式入口收拢；消息内等待、发送位停止 | H5一致，小程序等待阶段尚不一致 |
| 自然语言结束 | 有效 finish 回复保存后切换 | 处理中仍保持原状态；成功后收拢 | 失败不乱切已覆盖 |
| 结束后不足/失败/停止 | 仍为非访谈，材料保留，不自动计费重试 | 说明不足或单处错误与重试；可再开启 | 错误重复本阶段修复；重新开启后重试旧结束需明确 |
| 收起/返回/重开 | 保留模式、历史与输入；请求可后台完成 | 重开同一会话，不重发 | 主路径通过；跨作品/系统终止需补 |
| 采用/放弃/撤销 | 只有采用事务改正文；撤销追加恢复版本 | 查看与撤销同排，不误报采用本身为冲突 | 误报本阶段修复；撤销后的展示语义仍缺口 |

## 已确认的缺陷与处理顺序

后续无话题专项已修复下表中的“结束等待旧状态”“控制操作清空输入”“无话题开场”三项；417项测试、49项模拟器及H5四尺寸证据见统一会话验收。原始发现保留用于追踪，其余问题仍待处理。

### 本阶段修复并回归

1. **已采用结果误报冲突**：小程序 `openCandidate` 对所有状态比较生成基准，采用后必然不同；现仅 ready 结果判断过期。H5仅 ready 的过期结果显示重新调整，不因已采用而再次催促生成。
2. **停止反馈重复**：H5 controller.error 与 turn.error 使用不同取消文案，小程序又叠加页面 xiaowenError；现停止反馈交由对应助手气泡，保存异常仍由保存补救提示承担。
3. **模式事件冒充助手**：小程序两种页面把 system 消息套普通白气泡；改为无气泡的轻量系统事件，不删除历史。
4. **开启后未定位新消息**：H5只依赖最后turn，静态开启没有新turn；加入消息长度依赖，新增开场和系统事件也触发滚动。
5. **旧错误带入新访谈**：H5本地开启未清除控制器上一条阻断错误；开启时清除控制器提示，历史失败消息保留。

### 优先继续修复（未声称完成）

| 优先级 | 已读代码发现 | 后果与建议 |
| --- | --- | --- |
| 高 | `settleDialogue` 对非 confirm-edit 的任意 reply 清除 pendingEdit | 用户反问确认含义后原要求丢失；需要明确取消/替换，不能靠一般回复隐式清空 |
| 高 | H5收到结果后 `updateSession(..., deferSession=true)` 保存失败，只设置“已收到未保存”提示；失败结果未进入可恢复会话 | “重试保存/导出”是否真能保住已收到内容需专门故障注入验证；不能给无效补救承诺 |
| 高 | 小程序 `openXiaoWen` 把 preserve 失败吞掉仍跳访谈 | 未保存编辑可能在跨页读取时回退；应失败保留本页并提供重试/导出，不默默跳转 |
| 中 | 小程序结束等待页仍固定结束按钮，mode普通时还会显示“和小文聊聊” | 与唯一mode来源及紧凑头部不一致；按mode展示、处理中禁用，完成后沿原导航进入面板 |
| 中 | 小程序 runDialogue 的 onStarted 不区分 send/finish/change/retry，均清空 composer | 点击结束或换题会清除尚未发送草稿；H5这些操作保留输入；需按来源清空且保护后来输入 |
| 中 | 撤销仅新增版本，原turn仍 applied；两端仍显示撤销，小程序再次点击报冲突 | 保留“曾采用”历史与“当前已撤回”展示分离，不改写历史；定义派生展示状态并验证连续采用/手改/恢复 |
| 中 | 小程序历史仅列标题字数时间，无法查看/恢复具体版本 | 后续手改导致撤销受阻时，提示去核对记录却没有可执行路径；补查看与显式恢复，保留冲突保护 |
| 中 | `buildAiRequest` 素材只取最后24条，只有历史正文做相关度排序 | 长访谈回到早期经历可能遗漏相关材料；需要有预算的相关材料选择及遗漏证据 |
| 中 | H5非聊天页仍有“取消请求”进度条；小程序助手缺头像且字号15/25，访谈为18/30 | 相同会话因页面不同呈现分裂；统一状态组件与消息度量，不再逐处堆叠样式 |
| 中 | 无话题首次开启仍使用“围绕这个话题”的开场；已有任何消息一律“接着聊哪部分” | 问候过一次就跳过认识用户；应依据实际交流而非messages非空判断，且不能重开自动计费 |

## 后续验证应按场景，而非只数通过项

优先补：结束时输入框尚有未发送内容；确认改文后反问、纠正、再确认；采用A后手改再撤销；采用A再采用B后分别查看/恢复；新访谈中重试旧结束请求；请求结果保存失败后的原地救援；普通交流自然开启期间收起；访谈结束期间返回；不带话题/仅问候/长于24条素材的历史。

每个场景核对：持久模式、消息是否重复、素材来源、正文是否变更、当前可见操作、收起重开是否一致。真实模型效果、模拟器尺寸与真机键盘分别记录。整体变更保持活跃，不把本阶段布局44项模拟器通过解释为全流程无缺陷。
