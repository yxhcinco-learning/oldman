### 用户已明确的方向

- 自动保存继续作为默认后台能力，主要引导作者完成发表，不到处强调同步或保存说明；用户仍可只写草稿，不强迫发表。
- 编辑文章后增加“下一步”，进入发表环节，配置封面、预览阅读效果，再点击“发表”。首版新增配置仅封面，不扩展分类、标签、摘要等表单。
- 底部“文章”改为公共文章区域；原有私有作品管理移到“我的 → 我的文章”。原作品不因入口调整自动公开或丢失。
- 用户发表的文章进入后台审核，通过后才对其他用户展示；测试账号支持配置自动审核通过。

### 建议的首版体验

以下为本轮梳理的推荐方案，供下一会话细化确认，不代表已经实现或已经逐项获用户确认。

| 入口 | 主要内容与操作 |
| --- | --- |
| 热门 | 继续展示运营精选话题，保留直接写作、小文采访入口；与用户发表文章区分 |
| 文章 | 其他用户可阅读的已审核文章列表及阅读详情，展示封面、标题、作者、发表时间；建议按发表时间倒序分页，保留明显的“写文章”入口 |
| 我的 → 我的文章 | 作者自己的全部作品，每篇只占一条，查看草稿、审核中、已发表或未通过状态，继续写、查看发表结果；回收站、备份与恢复继续可达 |
| 编辑 → 下一步 | 先保存当前正文，进入发表设置；返回编辑保留正文及已选封面，不能另建一篇或丢失输入 |
| 发表设置 → 预览 → 发表 | 选择/更换封面，可预览列表封面与文章阅读效果；普通账号提交成功显示“已提交审核”，通过后才显示“已发表”，提供回到我的文章或查看文章的适用入口 |

建议封面必选，支持从手机选图、调整裁切及预览，沿用服务器图片处理能力；首版不增加 AI 配图或外部图库。标题和正文沿用编辑结果，提交前检查非空，缺标题时引导补标题，不新增重复表单或额外长文门槛。封面取消、上传失败、返回和重启都应保住已保存正文与发表设置，失败不假报提交成功。

“下一步”应在正文编辑页清晰可达，与语音/小文操作分工，适配键盘和底部安全区，不用大段教学文案推动发表。只提交作者确认采用的正文；小文对话、访谈素材、未采用候选、版本历史和待确认输入不进入发表内容。预览与公开阅读保留适用的 AI 来源标识。

### 私有作品、投稿与公开版本的关系

建议采用“一篇私有作品关联投稿记录与已通过的发表版本”。自动保存只更新作者工作稿，点击发表才冻结当次标题、正文、封面及展示署名；审核针对这份固定内容，不能审核过程中悄悄变成后续改稿。公共列表只读取审核通过且仍有效的发表版本，不直接开放现有私有作品接口。

- 首次流程：草稿 → 点击发表 → 审核中 → 通过后已发表；未通过时只向作者显示简短原因，修改后可重新提交。后台提供待审核列表、完整投稿预览、通过、驳回及已发表内容下架，不允许管理员直接修改作者原文。
- 建议审核中最多有一份有效投稿，重复点击或响应丢失重试返回同一结果；作者可撤回审核再提交修改。后台旧审核操作不得把已撤回或已替换的投稿发布出去。
- 建议已发表后继续修改仍自动保存为私有工作稿，公开旧版继续可读；再次提交并通过后替换公开版本，不重复增加一张公共文章卡。新稿未通过时原已发表版保持，后台下架另算，不能用一个“草稿/已发表”字段混淆这两份内容。
- 建议提供作者撤回发表及后台下架：退出公共列表后详情也不可继续读取，私有原稿保留。已投稿/已发表作品删除、回收站与永久删除需在新规格统一约定；推荐在线先撤回投稿或公开版本，再完成私有作品删除，失败保留原稿和可重试状态，不能留下作者以为已删除的公开正文。

### 审核、公开范围与测试账号

本需求将当前[产品](PRODUCT.md)“不做公开作品社区”的范围扩展为审核后的文章公开阅读；[架构](ARCHITECTURE.md)中管理员不得读取私有作品的规则继续约束未投稿内容。新增管理员权限只读取作者明确提交的投稿及必要署名，不包括作者整个私有 WorkSnapshot、聊天、素材和未发表改稿。实施前同步修订相应产品、设计、隐私和 OpenSpec 边界，不能直接复用私有作品或私人头像地址作为公共接口。

建议“公共”首版指所有已登录小程序用户可读，沿用必须登录的要求，不新增匿名网页、搜索引擎收录、作者主页或站外阅读。署名在预览中可见，默认沿用当前昵称及默认头像，不额外强制完善个人资料；公开作者字段和封面另行定义受控展示数据，原始图片、凭据和私有账号资料不公开。

测试账号自动通过由服务端的明确账号名单和环境开关控制，默认关闭；不能依据昵称、客户端参数或“测试”按钮获得资格。仍执行正文/封面校验、版本核对、限额及正式发表事务，记录“测试账号规则自动通过”的审核方式与版本，不跳过审核状态记录。未在名单的用户必须人工审核，错误配置不得让全部账号自动通过。

实施前需确认的产品细节：封面是否必选及裁切比例、公开署名的具体范围、改稿重审与作者撤回/删除采用上述何种规则。实际联调前需确定测试账号的服务端身份、开关适用环境，以及测试文章是否进入真实用户可见列表；未明确时不启用自动通过，不在真实公共列表注入测试内容。这些是待定项，不把文档推荐方案当成用户已经确认。
