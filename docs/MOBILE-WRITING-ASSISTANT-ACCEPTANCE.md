# 移动写作与小文布局验收

## 范围与原因

本轮对应用户提供的图1–图5：修改说明列出“未变”内容、系统键盘弹出后编辑器工具离开可视区、文章优化菜单占用过高、正文语音缺少收起按钮，以及小文输入区过高且不能随文字增长。

图1的原因是旧逻辑只比较候选全文是否与原文完全一致：全文只要有一处变化，就直接信任并展示模型的整段说明，因此模型写出的“某句改为同一句（未变）”也会留下。现在模型指令禁止列未变项，共享结果校正再按说明条目删除明确“未变/保持不变/无需修改”和同引文替换；校正不增加 DeepSeek 调用，不改变候选正文。

## 实现证据

- 应用画布监听 `visualViewport.resize/scroll`，使用有效高度和非负顶部偏移；缺失 API 时保留 `100dvh`。页头和底部四项工具不收缩，正文区承担滚动。
- 正文语音默认展开，空闲或待确认时可收起；收起后保留48px展开入口，点击已选中的“语音”也可恢复。授权、连接、录音和收尾期间不提供收起，待确认文字不会因收起被清空。
- 优化菜单保留常规优化、两列四项、小文入口和页头修改记录，压缩重复文案、内边距和区块间距；按钮触控目标仍至少48px，极短高度继续内部滚动。
- 小文 textarea 从52px一行开始，按内容增高到148px，之后自身滚动；语音图标与72px“发送”同排。语音转写仍只填入可编辑文字，不自动发送。
- 说明过滤覆盖显式未变条目、相同引文替换、过滤后为空、全文未变和问答无正文五类边界；服务端入库和客户端显示复用同一幂等函数。

## 自动检查

- 定向测试：`tests/article-ai.test.ts`、`tests/article-ai-gateway.test.ts`、`tests/ui.test.tsx`、`tests/voice-panel.test.tsx`、`tests/design-baseline.test.ts`、`tests/speech-presentation.test.tsx`，73 项通过。
- 首轮完整 `npm run check`：192 项测试、类型、Lint、OpenSpec 严格校验和模块边界通过。
- `npm run build` 通过；随后再次执行完整 `npm run check`，192 项测试、类型、Lint、OpenSpec 严格校验和模块边界均通过。
- 本地真实浏览器覆盖 360×640、390×844、430×932 和1280×900：根/body `scrollWidth` 均等于 viewport；优化菜单最小按钮48px，360×640时弹窗491px高且 `scrollHeight === clientHeight`，底部小文入口完整位于视口内。
- 360×640会话中短输入框52px、语音48×48px、发送72×48px；400字输入后文本框封顶148px并自身滚动，发送保持可用。语音收起/展开前后正文逐字一致。
- 390px宽的键盘高度模拟把可视区压到420px：根画布0–420px，页头0–76px，正文76–348px，四项工具栏348–420px，正文焦点保持；无横向溢出，浏览器控制台无警告或错误。

## 未替代的真机验收

自动 Visual Viewport 事件只能证明布局按输入指标更新，不能替代物理设备。iOS Safari、Android Chrome 的系统键盘、浏览器工具栏收缩、切后台返回和真实麦克风仍保持待验；没有证据前不标记完成，也不强行归档 change。
