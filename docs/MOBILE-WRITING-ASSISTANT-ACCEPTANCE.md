# 移动写作与小文布局验收

## 范围与原因

本轮对应用户提供的图1–图5：修改说明列出“未变”内容、系统键盘弹出后编辑器工具离开可视区、文章优化菜单占用过高、正文语音缺少收起按钮，以及小文输入区过高且不能随文字增长。

图1的原因是旧逻辑只比较候选全文是否与原文完全一致：全文只要有一处变化，就直接信任并展示模型的整段说明，因此模型写出的“某句改为同一句（未变）”也会留下。现在模型指令禁止列未变项，共享结果校正再按说明条目删除明确“未变/保持不变/无需修改”和同引文替换；校正不增加 DeepSeek 调用，不改变候选正文。

## 实现证据

- 应用画布监听 `visualViewport.resize/scroll`，使用有效高度和非负顶部偏移；缺失 API 时保留 `100dvh`。页头和底部四项工具不收缩，正文区承担滚动。
- 正文语音默认展开；空闲且没有待确认文字时显示收起，待确认后同一控制区只显示“取消 / 完成”，两组状态不并存。收起后整个语音舞台隐藏，不保留展开条；正文单击恢复语音，350ms内快速点击两次切到当前页文字输入并聚焦。授权、连接、录音和收尾期间不提供收起。
- 普通正文不再进入独立段落编辑页，统一在当前页全文输入框中编辑；语音舞台里尚未并入正文的待确认文字仍可进入独立编辑页。旧恢复快照中的普通段落编辑会合并到正文并迁移到当前页文字模式。
- 优化菜单保留常规优化、两列四项、小文入口和页头修改记录，在一屏目标下恢复主卡、选项和区块的舒适留白；按钮触控目标仍至少48px，极短高度继续内部滚动。
- 小文 textarea 空内容固定52px，不再由 placeholder 的 `scrollHeight` 决定；提示精简为“问小文，或提要求”。实际输入后增高到148px，之后自身滚动，清空回到52px；语音图标与72px“发送”同排。语音转写仍只填入可编辑文字，不自动发送。
- 说明过滤覆盖显式未变条目、相同引文替换、过滤后为空、全文未变和问答无正文五类边界；服务端入库和客户端显示复用同一幂等函数。
