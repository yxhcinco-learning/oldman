## Context

真实编辑器位于 `features/writing/Editor.tsx`。文字模式使用原生 textarea；语音模式使用带编号的 `story-paragraph` 网格按钮和独立的 `empty-writing` 样式。编号列、横线、内边距以及不同的字体/行高造成用户截图中的差异。

用户已明确批准这两处视觉变更。本记录与现行设计规范共同替代旧的可见段落编号和语音空白提示约定；产品化其他行为仍受原规范约束。当前分支仍为 `codex/productize-local-writing`，不通过切换到历史 main、合并或推送来扩大本次范围。

## Goals / Non-Goals

**Goals:** 正文与空白提示跨模式一致；保留自然换行、单段编辑和存储恢复；补齐自动与浏览器证据。

**Non-Goals:** 新编辑器技术、数据迁移、改语音协议、真实付费联调、AI 模拟重设计、发布、真机 HTTPS 验收。

## Decisions

- 共用现有 `full-text-editor` 的排版基准，正式编辑器使用独立的正文/提示类名和同一提示常量。预览不再使用带网格/横线的 `story-*` 样式，避免影响仍使用旧类名的隔离 AI 模拟界面。
- 语音正文保留原生段落按钮，但只渲染文字；去除可见序号及包裹装饰，以正文行高表示自然段间的空行。按钮继承正文排版，保留读屏名称、键盘激活和焦点提示。没有采用只读 textarea 统一所有交互，因为这会移除已验收的单段编辑入口。
- 标题沿用原输入框。两种正文在同一布局下起始位置一致，正文空白提示共享字体/行高/颜色，文字输入继续使用原生 placeholder。
- 不改变 `Draft`、`Segment`、数据库和备份语义，不以清理原文空白或合并录音段落来消除视觉分段。语音未完成内容仍留在原待确认区。
- CSS 增量限定于正式正文，保持原基础样式指纹不变；新增针对正文结构和样式的测试，不通过重写基础指纹掩盖越界改动。

## Risks / Trade-offs

- textarea 与段落按钮的浏览器默认排版不同 → 显式继承排版并移除按钮装饰，核对空白、单段、诗歌、长文及不同宽度下的实际行高和位置。
- 去掉编号可能降低可发现性 → 保留原点击、键盘与读屏编辑入口，不新增常驻提示。
- 展示调整误伤数据或待确认语音 → 使用真实 IndexedDB 测试替身覆盖恢复与失败，语音状态使用现有无计费回归。
- 浏览器有既有作品 → 仅通过 UI 创建明确命名的非敏感验收作品，不直接读写或清空用户数据库。

## Migration Plan

无需迁移。先验证并本地提交变更规范，再实现、测试、更新验收并本地提交。不自动归档产品化变更，不推送或发布。若需要回退仅回退本次源码，不触碰浏览器记录。

## Open Questions

本次两处展示要求无待确认项。真实手机麦克风、系统键盘与 HTTPS 验收沿用产品化待办，不在本次模拟回归中宣称通过。
