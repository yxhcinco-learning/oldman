## Why

分享来的读者目前必须先登录，尚未读到内容就面临门槛；读完后也没有表达喜欢、保存文章和持续关注作者的入口。本次希望形成“好友分享 → 先读全文 → 产生互动意愿 → 主动微信登录 → 完成互动 → 收藏或关注后再来”的闭环。

## What Changes

- **2026-09-09 用户确认方案 02 及空态修正，明确授权推进实现。** 按已确认原型实施小程序、共享协议、服务及运营审核；H5 继续独立作为设计证据，不恢复退役 H5 产品。部署、上传及真实账号操作另行授权。
- 为好友分享文章增加游客只读例外：所有当前已审核发表文章、派生封面、公开作者页及已通过评论可读；历史已发表文章同样允许游客，不设置阅读范围。点赞、收藏、评论、送花、关注和个人数据继续登录。明确替代现有“任何产品页面都先登录”在这些公共路由上的行为。
- 阅读页增加点赞、收藏、评论、送礼与作者关注；登录后续接点赞/收藏/关注的明确意图，评论保留草稿并再次点击发布，送花回到面板再确认，不自动扣花。
- 一级文字评论，建议首期复用人工审核：发布者看到“审核中，仅自己可见”，审核通过公开；支持删除自己的评论与举报。首期不做楼中楼、评论点赞或私信。
- 小花花为免费虚拟礼物，建议每天首次有效登录或有效会话当天首次进入时自动领取 3 朵，每次送 1 朵、可累计。笔、墨、纸、砚展示灰色并标记“暂未开放”，没有获取或赠送通道。
- 增加作者公开主页、关注/粉丝/互关状态、我的收藏、我的小花花，保留个人中心现有创作结构；互关由双方单向关注推导，不能单方建立。
- 完整设计取消登录、网络失败、余额不足、重复领取、空列表、文章失效与账号切换；量化分享阅读到登录、互动及再次访问的转化，记录最小事件数据。

## Capabilities

### New Capabilities
- `public-reader-entry`：匿名分享阅读的白名单、隐私边界及登录续接。
- `article-interactions`：点赞、私有收藏、审核评论、每日花朵与赠礼账本。
- `author-relationships`：稳定公开作者身份、关注/粉丝/互关与个人入口。

### Modified Capabilities
- `wechat-identity-session`：主动登录规则增加公共阅读例外，其余受保护行为保持。
- `account-cloud-work-sync`：退出后仍可读公共内容，私有账号缓存继续隔离。
- `product-design-system`：增加公共阅读互动、礼物抽屉和关系页面的适老交互要求。

## Impact

后续实施涉及小程序账号路由守卫、登录返回、`article-reader` / `profile` / `articles`，新增作者/关系/收藏页面；共享公开协议与社交协议；服务端账号库迁移、公开投影、互动接口及运营评论审核。沿用 Fastify、SQLite 和微信主动登录，无新增付费服务、支付、购买、排行榜、算法推荐或推送消息。

本提案依赖当前 `add-article-publication-review` 已实现的稳定文章 ID 与审核生命周期，不能把该变更未完成的真机任务视为已验收。已协调其 `Authenticated public reading and friend sharing` 条款：登录文章 Tab 保留，已审核发表的分享阅读增加游客例外。该能力仍由发表变更负责首次归档，本变更的三项新能力约束具体社交及受众行为；双方共同保留一致条款，避免归档顺序回退权限。

数据边界：公开资料使用可公开的稳定作者标识、用户名和默认头像，不暴露私有自选头像、OpenID、工作稿、会话或待审正文。收藏仅本人可查，粉丝/关注明细首期仅本人可查；花朵不可交易、提现、购买或转赠余额。H5 中账号、审核、日期、余额与网络状态均为内存演示，分享不会发送消息。

评审入口：[H5 原型](../../../docs/design-demos/reader-social.html)。已确认默认值：每日 3 朵且不设过期、一次 1 朵、一级评论 1–300 字且先审后显、关注/粉丝明细仅本人可见。确认依据见任务 1.3。
