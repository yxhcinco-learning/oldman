## Context

动机与产品范围见 [proposal.md](proposal.md)，六份 delta 是确认实施后的目标行为。2026-09-09 用户确认方案 02 和空态修正后授权实施；以下 H5 限制描述已经完成的评审阶段，业务阶段按本设计推进小程序、数据库、服务及运营审核。尚缺真实验收时不提前同步正式规格或归档，不自动部署或上传。

只读核对显示，现有 `pages/article/index.ts` 使用 `accountPage`，`MiniPublicationClient` 的读取统一经过 `authorizedRequest`，服务端 `publication-api.ts` 的正文与图片同样强制账号会话，`PublicationStore.publicArticle/publicImage` 最后进入 `accountTransaction`。因此“先读后登录”涉及前后端完整权限路径，不能只加登录弹窗或移除页面遮罩。

现有好友卡片已经使用稳定 `articleId`、审核后标题及处理封面；`auth/navigation.ts` 只在内存保存登录返回 URL。阅读页用请求序号和服务实例隔离迟到结果，图片落盘后再核对文章版本。其公开 DTO 只有冻结 `authorName`，没有稳定作者公开标识；阅读页还会读取本人的发表状态以决定是否展示作者管理。`profile` 已有资料编辑、创作摘要和设置，适合增加简洁个人互动入口。

`auth.sqlite` 当前 schema 3 保存账号、私有作品、用户名归属和发表数据。`publication_articles` 保留稳定公开标识，`published_id` 指向不可变审核通过快照；私有作品删除在同一事务撤销公开内容。这个生命周期与事务边界需要继续成立。

现行 PRODUCT、隐私说明和活跃发表变更都承诺登录用户阅读、自选头像私有。新游客公开必须记录作者选择，不能把历史文章或头像统一放开。当前 `article-publication-review` 能力仍位于另一活跃变更，正式 `openspec/specs` 尚无该能力；本变更不对不存在的正式能力写 MODIFIED。

## Goals / Non-Goals

**Goals:**

- 通过窄范围匿名投影和显式互动鉴权，建立分享阅读、登录续接、评论及持续关注的闭环。
- 把社交数据放在独立账号表及服务，复用既有 SQLite 事务、会话校验和审核后台，保持私有作品聚合与备份兼容。
- 让领取、赠送、计数、取消、受众收回和文章删除在重试及并发下仍可解释、可核对。
- 在 H5 评审完整展示正常与失败路径，并明确分离原型、隔离联调和微信真机证据。

**Non-Goals:**

不恢复 H5 用户产品或 H5 账号同步，不引入支付、购买、提现、好友通讯录、私信、评论回复树、评论点赞、推荐算法、排行榜或主动消息推送；不改变云作品的建立、同步、冲突和备份协议。实施包含本地隔离数据库迁移；本轮不会部署、上传、迁移线上数据库或执行真实账号互动。

## Decisions

### 1. 作者同意决定游客公开，历史受众默认保留

为每篇稳定公开文章增加受众状态，建议用 `audience = 'account' | 'guest'`、`audience_version` 和独立同意记录。迁移时所有已有文章取 `account`；新版新投稿在发表设置清楚显示游客公开选项，未经主动确认不取 `guest`。服务端冻结本次选择，并以事务记录同意的账号、文章、时间和说明版本；旧客户端缺字段默认保留原值，不能无意关闭或扩大受众。

历史作者可在发表管理主动选择“允许未登录用户阅读”，看到影响后提交同意；这不改变已通过正文，也不授予后台阅读私有稿的权限。关闭游客公开无需重新审核正文，但须立即更新受众版本并使公开读取失效。改稿提交保存已确认受众，不能因不同客户端默认值自动覆盖。

匿名读取对正文、封面、评论、作者文章列表独立核对当前 `published_id`、已审核状态、作品未删除和 `audience`。登录文章接口继续读取原有登录受众文章，旧分享卡片和稳定 ID 保持。文章后续撤回时不承诺撤销微信已缓存卡片；受众说明及隐私文案写明这一实际限制。

直接把现有所有读取接口取消鉴权会扩大历史受众；用客户端判断受众则无法保护图片和直接请求。选择服务端窄投影加显式同意，可在保留旧行为的同时开放新闭环。

### 2. 分开公开 DTO 和本人互动态，补充稳定公开作者身份

新增 `publicAuthorId`，建议用单独随机标识表映射内部 `user_id`，不可由 OpenID、用户名或私有作品 ID 推导。现有文章仍保留投稿署名，作者主页显示当前用户名。公开头像保持默认资源，现有私有头像读取端点不复用为公共头像接口。

匿名文章投影建议包含 `id`、`publicAuthorId`、冻结署名、标题/正文、发表时间、内容版本、受众版本、AI 标识和公开点赞/通过评论/获赠小花花统计。作者投影只含公开 ID、用户名、默认头像标识、公开总数及当前读者有权查看的已发表文章。公开评论只含评论 ID、作者公开 ID/名称、默认头像、纯文字和公开时间。不传 `workId`、内部账号 ID、投稿 ID、自选头像 URL、库存或本人收藏状态。

本人状态用独立鉴权响应一次返回 `liked`、`collected`、关系方向及派生互关、花朵库存、今日领取状态和自己的待审评论。作者管理仍走本人发表接口；游客请求不得调用现有 `statuses()`。不用公共接口接收可选 token 并在失效时静默降级，以免账号失效和匿名读取的语义混淆。

分享继续只使用已核实当前公开版的标题、封面和稳定文章路径，可带固定来源枚举 `source=share`，不附带分享者账号、token、签名私图或联系人。主“文章” Tab 可保持现有登录入口；本次游客白名单集中在分享阅读、相应作者页和可见评论，不把写作、我的等页面整体开放。

### 3. 登录返回增加有限意图，评论与赠送保留再次确认

在 `auth/navigation.ts` 现有返回数据旁增加受限联合类型：公开文章/作者目标、`like`/`collect`/`follow` 的目标布尔状态，或 `comment`/`gift` 的重开面板意图。只接受应用白名单路由与合法公开 ID，不接任意 URL。每次意图有唯一标识、来源页面生命周期和发起时账号代次；连续点击共用一次登录入口，完成或取消后清理。

游客点赞、收藏、关注成功登录后先确认原目标仍有效，再执行一次设置状态的请求；这不是 toggle，因此相同状态重复续接不会变成取消。评论草稿仅在本次运行内存保存，并随明确登录续接进入编辑框，登录后再次点击发布。送花仅恢复面板并重新读取库存，确认才构造扣花操作。应用进程重启不自动恢复未提交草稿或执行未确认送花；不会把评论输入放入 WorkSnapshot、备份或账号作品认领。

已有账号发起的未完成互动不能在换账号后执行。游客新发起的明确意图只允许绑定本次主动登录取得的账号；离开页面、取消登录或目标失效后，迟到响应不能导航或填数据。评论已发送但结果不明时，仅在原账号下保留有限待确认操作并重试原 ID，不自动重新发送不同内容。

当前 `pages/login/index.ts` 将成功导航放在作品同步之后；社交返回需以有效账号确认为前提，把私有作品同步失败单独保留为同步问题，允许公开阅读和独立社交操作继续。编辑/发表登录仍沿用原有落盘、账号归属和作品恢复校验，不能把社交的宽松返回套入编辑器。

只保留原 URL 无法续接动作；登录成功统一自动发布所有动作又会导致评论或库存未经再次确认而改变。有限意图可复用已有导航并准确表达不同动作的确认边界。

### 4. 独立社交表共享事务，余额和回执可核对

建议通过新迁移模块升级账号库，迁移版本在实施时按实际最新 schema 确定，不能现在假定其他活跃变更不会先升级。表名是设计建议，实施可沿项目风格调整，约束和行为不变。

| 建议表 | 数据及约束 |
| --- | --- |
| `public_authors` | `public_id` 唯一、内部 `user_id` 唯一；不复制微信身份或私有头像 |
| `publication_audience_consents` | 文章受众版本、明确同意/关闭事件、说明版本与必要审计；不保存正文 |
| `article_likes` / `article_collections` | `(user_id, article_id)` 唯一，建立时间；收藏无公共查询 |
| `article_comments` | 评论 ID、稳定文章 ID、账号、1–300 字文本、审核状态及版本、时间；无父评论字段 |
| `comment_reports` / `comment_audit` | 必要举报、处理和审核记录；仅独立后台可查，限制理由长度 |
| `author_follows` | `(follower_id, followed_id)` 唯一并拒绝同一账号；两个方向独立 |
| `flower_accounts` | 账号余额和版本，余额非负；接收礼物不增加可送余额 |
| `flower_ledger` | `daily_grant` 或 `gift_sent`、增减数量、服务端日期、目标文章/作者、唯一操作和最终结果；同账号同日 grant 唯一 |
| `social_operations` | `(actor, operation_id)` 唯一、请求摘要和确认结果，不含 token；同 ID 不同输入拒绝 |

每日发放在“验证有效会话后的当天首次进入”显式受保护入口执行，使用服务端 `Asia/Shanghai` 日期；事务内尝试唯一日记录并增加 3 朵，已存在就返回当前库存。会话持续有效也可次日领取，不要求每天退出重登。前端当日成功后不重复请求，遇到未知结果可读取/重试；首次发放失败不阻塞阅读，库存暂不可用时禁用送花。

送花事务内先重新鉴权并核对原操作回执：已提交且请求摘要一致时返回原结果，即使文章后来撤下也不能把已扣款的未知结果误报为未送达。首次操作才继续读取当前已发表且调用者有权阅读的文章、拒绝本人、条件扣减 `balance >= 1` 并插入礼物账本。余额、送达记录与计数必须同时成功或回滚。只剩 1 朵时两个并发请求至多一个成功；相同操作重试永远返回原结果。赠送回执的去重不能因一般短期清理而失效；账本保留足够唯一标识，不向客户端返回无限流水。已送达不退回，获赠只是文章/作者统计，不形成余额转赠。

关系写入使用“设置为关注/未关注”等目标状态、操作 ID 和当前关系版本，快速反向操作串行处理；过期版本冲突则重新读取，不让迟到请求覆盖较新的选择。计数优先从唯一关系和有效状态查询，或在同一事务维护汇总；不能只在前端加减。先以索引和批量读取支撑当前 SQLite 规模，无需新增缓存服务或队列服务。

### 5. 评论走独立人工审核并跟随文章生命周期

评论以 Unicode 码点计数，首尾去空白，服务端强制 1–300 字；纯文字渲染，不解析 HTML、富媒体或任意链接为可执行内容。提交固定操作 ID 并持久化 `pending`，本人可见“审核中，仅自己可见”，文章作者不因拥有文章就能读取别人的待审评论。审核仅把评论在 `pending` 与匹配版本时变为 `approved`/`rejected`；作者自删、后台隐藏和文章失效优先，旧审核不能复活内容。

在 `features/topic-admin` 现有审核区旁增加独立评论队列/详情和举报处理，复用独立管理员登录、Origin/CSRF、版本检查及必要审计；不复用普通账号作为审核权限。评论者可删除本人评论，读者可举报公开评论，普通作者不获得举报人信息或删他人评论权限。首期无评论编辑，未通过后修改以新的明确提交进入审核，避免在已通过记录上绕过审核改字。

`publication-lifecycle.ts` 的撤回/下架/删除事务需同时使文章衍生公开内容不可读。关系、评论和礼物记录绑定稳定 `articleId`，改稿重审不复制。移入回收站/撤回时数据保持受限，恢复工作稿不自动公开；永久删除清除关联评论正文和可能包含评论内容的审核/举报说明，仅保留必要无正文审计及账本。收藏中的失效文章由服务端返回无原文/封面的占位，可以取消收藏；不把历史缓存当作可读副本。

先审后显沿用当前运营能力，能避免引入新计费审核服务；代价是评论不会立即公开。H5 和客户端需要明确待审与未通过状态，不能用乐观插入公开列表掩盖审核等待。

### 6. 接口建议与客户端落点

| 建议接口 | 权限与职责 |
| --- | --- |
| `GET /api/public/articles/:articleId`、对应 `/images/:variant`、`/comments` | 仅游客受众的有效公开投影，正文和图片分别核对受众与发表状态 |
| `GET /api/public/authors/:publicAuthorId`、对应 `/articles` | 默认头像、公开统计；文章列表仅游客可读项 |
| 既有 `GET /api/mini/articles...` | 保留有效账号读取旧受众文章及图片，并附符合白名单的公开字段 |
| `GET /api/mini/articles/:articleId/engagement` | 本人的互动态、关系和有界评论状态，账号有效才返回 |
| `PUT /api/mini/articles/:articleId/like`、`/collection` | 设置目标状态，operationId 与版本防重复/乱序 |
| `POST /api/mini/articles/:articleId/comments`、`/gifts` | 显式发布或确认送 1 朵，结果不明重试原操作 |
| 评论删除/举报动作接口 | 鉴权，确认归属与文章当前状态，长度及频率限制 |
| `GET /api/mini/authors/:publicAuthorId`、关注状态写入接口 | 登录作者页可读原登录受众文章，关注按当前账号执行 |
| `GET /api/mini/me/collections`、`/following`、`/followers`、`/mutuals` | 只取会话自身，不能通过 userId 参数请求他人明细 |
| `GET /api/mini/me/flowers`、当天进入确认接口 | 库存读取与幂等每日发放；读取本身不含客户端任意赠送数量 |
| 发表受众设置接口 | 本人、版本与明确同意校验；旧客户端缺字段不改变受众 |
| `GET/POST /api/admin/comments...`、举报处理接口 | 独立管理员鉴权、CSRF、版本与审计 |

公共与鉴权接口都使用固定方法/字段白名单、ID 校验和有限分页；文章/评论/关系默认每页 20 条，可限制正文体积并沿用公开图片派生尺寸。错误区分需要登录、目标不可用、请求过频、冲突、余额不足与暂时失败，禁止输出数据库异常或隐私字段。正式路径在实现时与现有网关和 Nginx 精确白名单一并登记，不能用扩大 `/api/mini` 匿名权限来省略路由工作。

小程序主要落点为 `pages/article`、`pages/profile`、`pages/articles`、`auth/page.ts`、`auth/navigation.ts`、`pages/login`、`publication/client.ts` 与 `services.ts`；新增作者、收藏及关系列表页面登记 `app.json`。正文/图片匿名请求使用独立公开读取 client，社交写入继续使用会话授权器。公开图片缓存与私有账号目录分开；每次重入或返回前台核实当前可用性，失效时清除可见正文/图像/评论，不能由磁盘缓存绕过受众收回。

共享层新增独立社交协议并扩展公开文章 DTO；服务层新增社交 API/store/schema，复用身份事务但不改变正文聚合 v3、JSON v6 或游客作品认领。运营侧增评论审核组件，现有文章审核和私有资料接口各保留职责。

### 7. 有界刷新、错误恢复与最小转化事件

阅读首屏优先正文与公开摘要，公开评论分页和本人互动态可独立失败。避免每个按钮各发一次状态请求；采用一份有界页面状态和本人聚合，图片按有限并发加载。页面隐藏停请求/计时，返回前台做一次合并刷新；相同账号与目标合并在途读，不在订阅或 `setData` 中形成反馈循环。现有账号代次与页面 sequence 校验继续作用于社交响应。

点赞等可以显示处理中，但最终状态与计数由服务端确认；失败回到已知状态。评论发布失败保留草稿；送花未知结果先确认原操作，按钮保持待核对状态，禁止盲目重新扣花。下架/收回受众一经确认即清理展示，库存读取失败显示暂不可用而不是 0，空评论和读取失败分别提示。游客读取与单账号写入设置独立有界频率桶，写入再按操作类别限频，不做持续轮询或自动重试风暴。

转化只记录最小事件：`share_entry_open`、`login_intent`、`login_success`、`interaction_confirmed`、`return_visit`，操作类别与公开文章 ID 足够解释来源；不记录评论文本、作者私有 ID、联系人、OpenID、token 或持久指纹。匿名入口只用本次会话随机短期标识连接同次登录意图，过期后不追踪跨会话游客；登录后的再次访问可按账号内部聚合为统计，不向运营列表输出个人阅读轨迹。沿用现有受限日志/聚合能力，不增加第三方分析服务；原始事件保留期限及访问权限在实施时与隐私说明统一记录。

“打开分享菜单”只计入口使用，不能认定实际送达；从分享来源进入才计对应阅读事件，互动成功以服务端确认或回执为准且去重。事件采集失败不能阻塞主流程。H5 中统计是演示，不记作真实用户转化。

### 8. H5 评审与真实验收分层

2026-09-09 方案 02 按评审反馈调整呈现：作者主页关注移至身份行右侧；“我的”创作区直接以既有 `author-center.html` 方案 06.1 的结构和样式为基准，保留分组右日期、整卡续写、字数圆箭头、全部篇数和两条缩进摘要，不能用模块内单独文字链接替代原入口。收藏取消收在每条作者/日期行右侧图标，保留独立 48px 热区并阻止误开文章。评论举报用“更多 → 举报评论”的二级动作，按评论 ID 保留目标和原列表滚动位置，取消、登录返回及完成后恢复原上下文。

正常页面删除收藏/关系/评论等开场介绍和装饰口号；不删待审、空态、失败恢复、每日领取、余额不足及礼物禁用等会影响理解和操作的状态。公开/私有权限语义保持，用户不必在每个列表重复阅读同一隐私说明。

原型使用独立静态文件、内存状态及非敏感示例，展示游客与已登录阅读、动作登录续接、评论草稿/待审/公开、库存/送花、灰色文房四宝、作者关注/互关、我的收藏/关系和文章失效。网页上的模拟登录、次日进入、审核和失败切换明确标记为设计控件，不进入正式产品。

H5 按 360×640、390×844、430×932 和桌面检查布局、触控、弹层滚动、键盘可达、无溢出、焦点与取消恢复。该层只能验证页面及内存状态机，不证明微信授权、真实赠礼或审核有效。

用户确认后，服务端先做真实本地 HTTP/SQLite 隔离联调：两个账号、迁移旧受众、匿名白名单、待审不可见、唯一关系、领取跨日与并发、赠送原子性、丢失响应、旧会话和删除回滚。微信换码可使用替身，必须在证据中明确；普通回归不调用付费服务。客户端运行项目完整 check/build 并刷新小程序 npm 包，模拟器验证实际三种尺寸和生命周期；测试替身不得冒充真实账号。

最后单列真机证据：两个微信账号真实好友收发，游客打开新开放文章，历史文章保留登录门槛，五类互动登录返回，真实评论审核可见性，跨日或受控服务时钟的领取边界，送花库存一致，账号切换及文章撤下。真实自然跨日与隔离时钟结果分开记录。继承发表变更仍缺少的真机任务，不以本轮 H5 或历史测试数量补记通过。

## Risks / Trade-offs

- 历史作者只同意登录阅读 → 所有旧文章默认 `account`，明确记录主动开放，不批量默认为游客公开。
- 新公共接口意外暴露内部字段或私图 → 独立 DTO、独立公开路由、正文/图片/评论各自状态检查，匿名直连与参数枚举纳入回归。
- 登录导航依赖私有同步，导致互动被无关失败困住 → 社交按有效会话与目标状态续接，作品同步错误单独处理，写作入口保持原保存门禁。
- 每日赠送被重试或并发多次结算 → 服务端时区与唯一日记录、余额条件更新、账本与回执原子提交，永久保留必要去重标识。
- 人工审核延迟影响评论体验 → 本人待审状态清楚可见，独立后台队列和举报处理；不承诺即时公开。
- 大正文、多张图片和社交请求增加网关压力 → 首屏数据聚合、20 条分页、有限并发及分级限流，无周期轮询，读失败不连锁触发全页同步。
- 文章更新使旧评论语境变化 → 评论绑定稳定文章并保留时间；作者正常重审不复制互动，永久删除清理正文衍生内容。
- 私有关注名单限制公共社交发现 → 首期仅显示公共计数和本人关系，以作者已发表文章承担发现路径，后续扩大名单受众需另行明确设计。
- 原型看起来已可用 → 常驻设计演示标识、模拟状态控件与 README 说明，交付只声明 H5 证据，真实任务保持未勾选。

## Migration Plan

1. 本轮完成并验证规划和 H5，交付用户评审；收到确认后才进入业务实施，不在本轮修改正式规格、服务或数据库。
2. 实施开始核对最新 schema 与活跃 `add-article-publication-review`。协调其 `Authenticated public reading and friend sharing` 完整条款，明确本变更取代的游客例外和旧受众保护；若它先归档，基于新 main spec 追加合法完整 delta，若仍活跃，更新依赖变更及归档顺序，防止后归档覆盖新权限边界。
3. 增补账号库事务迁移、公开作者映射及社交表；对历史文章设置登录受众，不回填任何领取/互动数据。备份与回滚脚本的 schema 上限随新版本更新，在隔离旧库迁移/失败回滚中保留原账号和作品。
4. 经完整后端与客户端隔离验证后，按用户另行授权的发布范围部署支持新 schema 的网关并开放精确路由，再更新客户端；运营评论审核必须在评论入口启用前可用。需要上线时分别记录网关、后台和小程序版本，不因本轮提案自动执行发布。
5. 若启用后需停止新增社交操作，可通过有界功能开关关闭写入/新游客开放并保留已确认数据与旧登录阅读，界面提供真实不可用说明。数据库已写入新数据后，不把旧 schema 3 程序强行连入新库，不恢复历史备份覆盖新数据；修复采用兼容迁移后的版本。
6. 实施及相应真实验收完成后再同步正式规格和归档；没有真机证据的任务保持活跃并说明缺口。每日 3 朵、每次 1 朵、一级 1–300 字先审后显和关系明细本人可见是本次提交评审的明确默认值，由本次规划/H5确认一并决定，不增加重复审批阶段。
