## Context

文章助手的输入框使用全局 2px、4px 外偏移聚焦线，但其祖先为独立滚动容器，边缘聚焦线会被裁掉。现有 `VoicePanel` 已通过 `SpeechSession` 和 `HoldGesture` 接通腾讯云实时语音，但只服务正文录入；文章助手的自由输入没有语音转文字入口。编辑器工具栏一直显示“优化”，却没有在用户已有足够正文时解释用途。

## Goals / Non-Goals

**Goals:**

- 让会话输入框聚焦状态四边完整、清楚且不造成布局跳动。
- 在文章会话中复用现有腾讯云语音链路，把识别文字写入待发送输入框。
- 用一次性、可关闭、靠近“优化”按钮的提示帮助首次用户发现文章整理能力。
- 保持适老化触控尺寸、知情授权、取消与失败反馈。

**Non-Goals:**

- 不实现实时语音聊天、自动发送、语音朗读或新的语音供应商。
- 不改变文章 AI action、DeepSeek 请求、正文写回或备份格式。
- 不重做编辑器主语音面板，也不将引导状态同步到其他设备。

## Decisions

### 会话语音只负责听写

新增紧凑的 `VoiceDictationButton`，复用 `SpeechSession` 和 `HoldGesture`。开始一段录音时保存当前输入框文字，实时识别结果追加在其后；取消恢复录音前文字，结束后保留可编辑的识别文字。用户仍需点击“发送”，因此语音识别不会直接触发 DeepSeek 或正文修改。

选择紧凑听写按钮而不是复用完整 `VoicePanel`，因为后者包含正文待确认、清空、完成和段落编辑语义，会把会话输入与文章正文混在一起。按钮继续使用同一腾讯云状态接口、WebSocket、浏览器麦克风与授权说明，不增加服务端接口。

### 共享语音授权记忆

编辑器语音和会话听写使用同一个本机 `localStorage` 授权标记。首次长按仍显示“音频发送给腾讯云、不保存原始录音”的说明；同一浏览器同意后不因切换页面重复询问。无法访问 `localStorage` 时只在当前组件会话记住，不阻止使用。

### 聚焦线改为输入框内部

会话 textarea 单独覆盖全局外偏移 outline，改用边框加内阴影的聚焦样式。这样无需放宽滚动容器或改变弹层宽度，也不会在 360px 小屏产生横向滚动。

### 提示出现即记为已展示

以当前有效正文去除空白后的 80 个字为阈值。首次达到阈值时，在“优化”按钮上方显示非模态提示，并立即写入 `suiyue-optimize-tip-v1`；关闭、点击“知道了”或点击优化均隐藏当前提示。把“已展示”写在出现时可以保证刷新或换文章后不会反复打扰。`localStorage` 不可用时仅保证当前挂载期间出现一次。

提示不自动取得焦点，也不遮挡正文输入；关闭按钮和“优化”按钮均保持至少 48px 目标。文案固定为“写好一段后，点‘优化’，小文可以帮您整理语句、分段和标点。”

## Risks / Trade-offs

- [识别中的会话被关闭] → 组件卸载时取消 `HoldGesture` 和 `SpeechSession`，不发送文章 AI 请求，已经写入输入框的识别文字随会话内 prompt 状态保留。
- [浏览器拒绝麦克风或网关未配置] → 显示现有短错误，保留原输入，允许继续键入。
- [已有长文首次升级时立即看到提示] → 这是一次性功能发现提示；不抢焦点且可直接关闭。
- [授权标记只保存在浏览器] → 符合现有本机产品边界；清理浏览器数据后会再次询问。
