## Why

现有话题后台虽然功能完整，但信息架构仍接近内容展示页：导航、列表、详情和监控彼此割裂，宽屏空间利用不足，常用状态与待办不够集中，视觉上也缺少成熟运营后台应有的稳定框架。需要在不改变话题数据、权限与发布规则的前提下，重组为适合日常高密度管理的企业后台。

## What Changes

- 将后台改为深色固定侧栏、白色顶栏和浅灰工作区组成的统一管理台，使用系统无衬线字体、标准线性 SVG 图标和紧凑密度。
- 新增登录后的工作台总览，集中展示话题状态、首页席位、近期操作与服务配置，并提供明确的常用入口。
- 将话题内容改为全宽数据表格管理，筛选和主要操作集中在工具栏；选中话题后用右侧详情抽屉承载编辑、真实用户端预览、发布与修订操作。
- 将生成与新建、首页排期、生成与审计、运行监控纳入同一后台框架，统一页面标题、面包屑、状态标签、空态、加载态、错误反馈和操作层级。
- 手机端改为可展开的侧栏导航与单列页面；表格用紧凑卡片行表达，详情抽屉占满可见宽度，排期与紧急下线继续可完成。
- 保持所有现有管理 API、认证、CSRF、并发前置条件、AI、审计和公开端行为不变，不新增外部服务或运行时依赖。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `topic-editorial-workflow`: 调整内部话题后台的信息架构、工作台总览、表格与详情抽屉交互，以及桌面和手机响应式要求。

## Impact

主要影响 `features/topic-admin` 的 React 页面与 CSS、后台 UI 测试、`DESIGN-SYSTEM.md` 和浏览器验收记录。服务端 API、数据库 schema、登录凭据、公开话题接口、用户端与小程序均不改变。
