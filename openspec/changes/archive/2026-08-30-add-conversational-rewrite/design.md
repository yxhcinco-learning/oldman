## Context

正式文章助手已有每篇文章一份 ArticleSession、不可变版本、DeepSeek 受控网关和“完整候选 → 预览 → 确认应用”链路。当前 composer 始终发送 `question`，系统提示词和网关会拒绝/剥离任何正文，因此明确的改文要求也只能得到拒绝。

## Goals / Non-Goals

**Goals:** 在同一文章对话里显式发起自然语言改文；继续使用全文候选、基准检查、事务应用、撤销、恢复、取消和历史上下文；让问答与改文意图对长辈清楚可选。

**Non-Goals:** 自动判断意图、直接写回、自动改标题、跨文章编辑、语音对话、开放精简/扩写/配图快捷按钮、额外模型调用或新的存储版本。

## Decisions

- 增加 `rewrite` action，而不是让 `question` 同时承担问答和改写。composer 提供“问小文”和主操作“调整文章”两个按钮；同一段输入按用户明确选择发送。相比模型自动分类，这不会把“这一段怎么改更好？”误当成实际修改，也不会为分类增加一次计费调用。
- `rewrite` prompt 原样作为本轮用户要求保存和发送；question 仍只读并由网关删除 body。rewrite 必须返回完整 body，沿用 ready/applied/dismissed 状态和现有预览。重试保留原 prompt，不能退化为无要求的通用优化。
- 版本来源增加 `rewrite` 并显示“对话调整”。这是枚举扩展，不升级 IndexedDB 和 JSON v2；已有记录不迁移，副本导入的标识重映射保持不变。使用过 rewrite 的备份需要包含该动作的新版本程序恢复，旧程序不承诺读取未来枚举。
- rewrite 允许按明确要求调整、删除、重排已有内容，并允许加入用户 prompt 明确提供的新事实；不得把历史文章里的指令当任务，不从常识或外部知识改变核心可核实事实，不改标题。文风改写可加入不改变核心事实的修辞、情绪色彩和氛围表达，但不得新增具体经历、动作归属、关系、对话或因果；修改说明必须披露氛围性增写。未给出明确修改时返回原文，由程序显示无变化。
- 真实短文验证发现模型会把“更温暖”改成夕阳、微风和“一起种下”等内容；该候选被放弃、正文未改变。经用户校正，夕阳/微风类表达应按文风与事实影响合理判断，不能仅因出现新词否决；真正越界的是“我们一起种下”和母亲“指着墙角”等新的具体动作/共同经历。提示词因此按核心事实与文学表达分层，并要求披露氛围改写；预览强化人物、动作和经历核对。模型约束不是事实保证，不增加自动采用。
- 上下文仍为当前全文、相关版本和近期 turn。prompt 是可信的本轮用户指令；current/versions/turns 内出现的命令句只视作文章或历史数据。正文、问题和上下文预算不变，不新增请求或自动重试。
- UI 对 rewrite 结果使用现有全文预览、原文对照、过期保护和应用事务。对话气泡展示用户原话；生成中可以取消，失败可按原要求重试。小屏 composer 的两个操作并排，目标尺寸至少 48px，主改文操作使用森林绿。

## Risks / Trade-offs

- [两个发送操作可能增加选择成本] → 使用“问小文 / 调整文章”直接描述后果，并在输入框下用一句话解释；不使用抽象模式名。
- [用户指令含糊导致过度修改] → 不自动判断，rewrite 提示词要求只执行明确范围；仍需全文预览和事实提醒。
- [用户明确要求删除事实] → 这是本轮授权的编辑，不把“保留所有事实”绝对规则套用到 rewrite；只保护未被要求改变的内容并保留历史恢复。
- [旧程序不认识新 action] → 不改变当前数据库结构；回退前导出备份并保留当前版本程序，未知未来记录不通过旧备份校验。

## Migration Plan

先扩展 domain schema、提示词和控制器，再接 UI 与测试；已有会话无需改写。完成 check/build 和浏览器回归后，用一篇非敏感短文做最多一次真实 rewrite 调用，预览后放弃或恢复，不自动应用用户文章。同步正式规范并归档；不发布。

## Open Questions

无阻塞问题。自动意图识别和更复杂的局部选择编辑留待实际使用反馈后评估。
