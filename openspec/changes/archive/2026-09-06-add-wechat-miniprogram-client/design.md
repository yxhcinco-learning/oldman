## Context

当前正式版是 React/Vinext H5：作品、采访素材和文章会话保存在浏览器 IndexedDB，正文语音由 Web Audio/AudioWorklet 生成 16 kHz PCM16，通过同源 WebSocket 交给回环 Fastify 网关；话题和 DeepSeek 也通过同源 HTTP 访问。公网体验入口由 Nginx Basic Auth 保护，网关把精确浏览器 Origin 当作请求边界。现有领域模型、备份校验、AI 协议和服务端上游适配大多是平台无关 TypeScript，但 React 组件、DOM 光标、Visual Viewport、文件下载和采音实现不能运行在微信小程序。

用户已确认：借用 `ask_job` 的 AppID 只用于开发/体验版；第一版作品不上云；用户会在实现后手工把 AppSecret 写入指定服务器环境文件；小程序尽量保持当前交互，但允许以平台原生方式替代无法可靠复刻的浏览器细节。现有网页继续维护，当前两个活跃变更的未完成试点和真机证据不会被本变更冒充完成。

## Goals / Non-Goals

**Goals:**

- 交付可在微信开发者工具和真实微信中运行的原生 TypeScript 小程序，保留现有写作、话题、采访、小文、版本、回收站和备份闭环。
- 用 `wx.login` 建立无可见注册步骤的最小内部身份，为 AI、语音和将来可选云备份提供可信服务端主体。
- 作品继续本地优先；离线、登录失败或线上服务不可用时，已有作品和普通文字编辑仍可使用。
- 复用领域/协议和现有腾讯云、DeepSeek、话题上游，明确隔离浏览器与小程序的平台适配层。
- 在不移除网页 Basic Auth 的前提下，为小程序提供独立、可撤销、有限流的 HTTPS/WSS 鉴权边界。
- 把临时 AppID、更换正式 AppID、隐私授权、AI 标识、平台配置和真机验收的限制显式交给用户和发布流程。

**Non-Goals:**

- 第一版不上传、同步或合并作品、采访素材、会话、原音与备份，不提供跨设备恢复。
- 不请求手机号、头像、昵称，不增加登录/注册页、密码、验证码、账号中心或社交身份。
- 不用 WebView 包装现有 H5，不迁移到 Taro/uni-app，也不删除或降级现有网页端。
- 不在临时 AppID 下提交正式审核或发布，不承诺临时 AppID 到正式 AppID 的 OpenID 或本地数据自动迁移。
- 不在本变更内完成小程序备案、类目申请、最终 AppID 注册、平台后台配置、上传、提审或发布；这些外部操作均保留显式授权门槛。
- 不把开发者工具、桌面录音、测试替身或配置成功当作真实 Android 微信和真实上游验收；未执行的 iOS 验证必须如实标注，不得冒充通过。

## Decisions

### 使用原生 TypeScript 小程序而不是 WebView 或跨端 UI 框架

正式小程序放在 `apps/miniprogram`，使用 WXML/WXSS/TypeScript、原生页面生命周期、`RecorderManager`、`FileSystemManager`、`wx.request` 和 `wx.connectSocket`。提交的 `project.config.json` 使用 `touristappid` 或无业务归属的安全占位；本机未跟踪的 `project.private.config.json` 写入临时 AppID。

WebView 虽能最快展示 H5，但不能解决浏览器本地库、Basic Auth、录音兼容和微信身份的根问题；Taro/uni-app 仍需重写 DOM、Web Audio 和存储适配，并增加一层大型运行时。当前界面规模允许原生实现，原生能力也更容易在开发者工具和审核环境中验证。

### 抽取共享核心，界面和平台能力保持独立

领域对象、版本/备份校验、话题与 AI 协议、状态转换和固定业务规则进入可被网页、网关和小程序消费的共享 TypeScript 包；现有导入路径可先以薄重导出保持兼容，按小阶段迁移。共享包不得引用 React、DOM、Node-only API 或 `wx` 全局。

网页端继续使用 React、IndexedDB、fetch、WebSocket 和 AudioWorklet；小程序端分别实现本地文件仓储、请求客户端、Socket 客户端、录音、键盘/安全区和备份文件选择。相比复制整套领域代码，这能让两个客户端共享相同 schema、字符上限、候选确认和备份兼容测试；相比一次性重排整个仓库，薄适配迁移更易回滚。

### 小程序保持信息架构和显式主操作，浏览器隐藏手势降级为辅助

“热门 / 文章 / 我的”继续作为固定底部导航，并声明为微信 `app.json` 的三个官方 tab 页；用 `custom: true` 和根目录 `custom-tab-bar` 保留 H5 选中态，各页在 `onShow` 通过 `getTabBar()` 同步当前项，主导航只用 `wx.switchTab` 切换，不再把页面级组件放在内容流末尾模拟底栏。话题详情的两条入口、文章页固定新建、标题编辑、语音/文字切换、小文面板、采访单一发送、候选预览确认和修改记录保持相同语义。原生 `<textarea>` 承担文字编辑，键盘高度使用微信事件与安全区调整；小文使用稳定的自定义抽屉或页面层，输入区固定可达。

现有 H5 的 Echoes of Time 页面和 `app/globals.css` 是小程序视觉基准：颜色、字号层级、圆角、间距、卡片插画、底部标签选中态和编辑器停靠区使用与 H5 对齐的 CSS px，不再按屏幕宽度用 rpx 等比放大。产品页面使用自定义导航避开微信状态栏与胶囊，不再同时显示系统标题栏和页面内标题栏；编辑器页头只保留返回与可点击标题，右侧用等宽空位平衡布局并避开微信胶囊，不提供重复的手动保存按钮。正文和标题停顿后自动保存，用户点击返回时等待最后一次本地写入并直接退出，不再二次询问；真实写入失败则留在编辑页提供重试与救援导出。“开始写作”仅出现在“文章”页底栏上方。微信胶囊、安全区、原生授权弹窗和来源 `web-view` 的系统返回栏属于平台保留差异，其余页面不得另造一套放大版样式。

正文长按录音和明显的语音/文字切换按钮作为验收主路径。浏览器中依赖 `caretPositionFromPoint` 的双击/长按精确落字符若无法由微信稳定提供，允许切到目标段落或文末，并明确显示文字编辑器；不得用逐字节点模拟光标而牺牲性能、可访问性和长文稳定性。

### 登录在后台启动，但本地写作不以登录成功为前置条件

小程序冷启动读取本地业务 token，并以单飞请求调用 `wx.login` 和 `POST /api/mini/auth/wechat` 补建或更新会话。界面不显示登录/注册，也不请求用户资料。登录断网、换码失败或服务未配置时，只将在线能力标记为不可用；本地作品列表、编辑、回收站和备份仍可进入，用户触发话题刷新、AI 或语音时看到具体、可重试的在线错误。

服务端使用运行时 `WECHAT_MINIPROGRAM_APP_ID` 与 `WECHAT_MINIPROGRAM_APP_SECRET` 调用 `code2Session`。只接受一次性 code；以 `(app_id, openid)` 查找或创建内部用户；不把 OpenID 当作客户端凭证，不把 AppSecret 或 `session_key` 下发、写日志或写入客户端包。当前没有解密微信资料的需求，因此 `session_key` 使用后即丢弃，UnionID 也不作为自动合并身份的依据。

### 使用最小 SQLite 身份库和随机可撤销会话

Node 24 自带 SQLite 能力足以承载首批用户与会话，无需新增付费数据库或复用其他项目的数据实例。当前固定的 Node 24.14.1 仍把 `node:sqlite` 标为实验能力，因此实现必须把它封装在窄仓储适配器后、固定并验证服务器 Node 版本，且不得让实验 API 形状进入领域层；若部署验证发现该固定运行时不可接受，再在不改变 schema/接口的前提下切换到经 Node 24 安装验证的 SQLite 驱动。数据库位于 release 外的 `/var/lib/suiyue-yousheng/auth.sqlite`，使用受限目录、WAL、事务、启动迁移和独立备份。数据表只包含内部用户、`(app_id, openid)` 身份、会话 token 哈希、创建/到期/撤销/最近使用时间；不保存作品或微信公开资料。

客户端收到高熵随机 opaque token，服务端只保存 SHA-256 哈希并限制有效期、每用户活动会话数和失效清理。小程序优先用支持加密的异步 storage 保存 token；若安全持久化失败，则本次运行继续使用内存 token，下次冷启动重新无感登录。选择可撤销随机 token 而不是只签名 JWT，是为了在借用 AppID、设备丢失或密钥轮换时能够立即使会话失效，且不再引入第二个长期签名秘密。

### 小程序 API 使用命名空间和业务鉴权，不放宽网页现有边界

Nginx 对网页与原 `/api/ai/*`、原 `/api/speech` 继续要求 Basic Auth；只对明确列出的 `/api/topics`、`/api/mini/auth/wechat`、`/api/mini/ai/turn`、`/api/mini/speech-ticket` 和小程序语音 Upgrade 关闭 Basic Auth，并分别施加 IP、用户与应用级限流。Fastify 小程序路由不依赖浏览器 Origin，必须验证业务 token；登录与已审核话题是例外，其中登录受严格速率和响应大小限制，话题保持只读公开缓存语义。

小程序先以 Bearer token 申请 60 秒内有效、只可消费一次的语音 ticket，再用 ticket 建立 WSS。长期 token 不写入 WebSocket URL，ticket 不写访问日志；网关消费 ticket 后仍施加现有连接、时长、字节和上游缓冲限制。这样既不假设所有微信平台都稳定发送自定义 WebSocket Header，也不因取消 Origin 检查而把语音入口公开。

### 作品按聚合文件保存，小索引可重建

小程序将每篇作品、草稿快照和对应文章会话写入 `wx.env.USER_DATA_PATH` 下的版本化聚合文件；作品列表索引、活动作品恢复和少量设置使用独立小文件或小型 storage。聚合文件是事实来源，索引只作缓存并可通过扫描有效文件重建。写入采用同目录临时文件、完整 schema 校验和替换；AI 候选应用、恢复与版本追加在同一作品聚合中原子完成。

若聚合已写而索引或 recovery 尚未更新，启动时以有效 revision 和时间选择较新数据，不把旧 recovery 覆盖到新作品。连续保存通过单写队列与 expected revision 拒绝过期写；空间不足、系统清理、文件损坏或写入失败时保留内存副本，显示未保存并提供重试/救援导出。选择用户文件而不是只用 `wx.setStorage`，是因为现有备份与长期全文版本可能超过单 key 及总缓存限制。

### 备份是客户端之间唯一的显式迁移路径

网页和小程序继续产生同一受验证、有限大小的版本化 JSON 业务格式；小程序使用微信文件选择/分享能力导入导出，导入始终重映射为新副本。临时 AppID、正式 AppID、不同微信用户、网页 Origin 与不同设备之间不自动读取数据，界面必须在体验版和“我的”中说明这一点。更换正式 AppID 前，若需要保留测试文章，用户必须先导出，再在正式 AppID 中手工导入。

### 原生录音适配现有 PCM 上游协议

小程序在用户按下时立即显示按压反馈，持续 180 毫秒后才进入隐私/麦克风授权；短于阈值的触摸不请求权限或在线服务。授权后先以显式 JSON `POST` 取得语音 ticket、连接 WSS 并等待网关 ready，再启动 `RecorderManager`：16 kHz、单声道、PCM、有限 duration、启用分片回调。客户端把任意大小的 `ArrayBuffer` 以偶数字节边界缓存和转发，不假设每个回调恰好等于腾讯建议分片；剩余完整采样在正常停止时发送，随后发送 end。音量从 PCM 计算，只用于本地反馈，不上传额外指标。

松开、取消、授权期间松手、切后台、系统中断、Socket 失败或超限都停止 recorder、注销本轮监听并关闭/取消 Socket；会话 ID 隔离迟到帧和结果。已有转写保留为待确认内容。开发者工具录音只证明流程可运行，当前验收至少由真实 Android 微信验证；iOS 在设备可用时作为后续兼容性增量补充，未执行前不得声称通过。

### AI 标识绑定候选与导出，不冒充用户原文

聊天回答以小文身份和助手气泡区分，不重复 AI 核对提示。完整候选和预览保留“AI 辅助生成/请核对”说明；采访原始回答、用户手写正文和议题来源不被标成模型输出。候选只有明确应用后才影响正文，现有 ArticleSession 继续保留 applied/dismissed 与版本来源。

单篇 TXT、复制正文或其他面向外部使用的导出若包含已应用 AI 候选，必须在文件或复制内容中带可见 AI 辅助标识；全量 JSON 备份保留机器可读来源和用户可读说明。第一版采用保守判定：作品会话存在已应用生成候选即标识，避免在用户后续手改后错误删除披露。确切文案、文件元数据和平台审核材料在提审前按现行规则复核，但不得以“用户已确认”为由静默去除标识。

### 密钥只由用户写入服务器固定位置

2026-09-06 补充授权：用户明确要求代理代配置正式 AppID/AppSecret 并联调，替代本次手工填写步骤。仅经受限本地临时文件和专用 SFTP 传递秘密，不进入客户端、Git、TAT 命令/输出；保留旧服务器配置及本地业务备份，配套验证后清理传输文件。该授权不包含小程序上传、提审、发布或其他应用凭据改动。

仓库只提交 `deploy/runtime.env.example` 中的空字段：`WECHAT_MINIPROGRAM_APP_ID=`、`WECHAT_MINIPROGRAM_APP_SECRET=`、`SUIYUE_AUTH_DB_PATH=/var/lib/suiyue-yousheng/auth.sqlite`。真实 AppSecret 由用户手工写入服务器 `/etc/suiyue-yousheng/runtime.env`，保持 `0600 root:root`；实现和验收输出只报告字段是否存在，不回显值。小程序 AppID 不是秘密，但临时 AppID 仍只写入未跟踪的本机 private config，避免误把借用身份变成仓库默认发布目标。

## Risks / Trade-offs

- [原生重写导致网页与小程序行为漂移] → 共享 schema/状态转换和契约夹具，两个客户端各做呈现测试；不共享 UI 组件伪造跨端一致性。
- [临时 AppID 被误上传或积累真实数据] → 提交配置不含真实 AppID，CLI 上传/提审不进入常规脚本；体验版显示非正式数据边界并提供备份。
- [登录服务不可用阻断目标用户] → 登录后台进行，本地写作不设登录门；在线动作才要求有效会话。
- [Origin 豁免扩大 AI/语音暴露面] → 使用专用命名空间、Bearer 会话、一次性语音 ticket、分层限流和最小日志，不修改原网页路由策略。
- [身份数据库在 release 切换或磁盘故障时丢失] → 数据库置于 `/var/lib`，迁移前备份、WAL 检查和回滚只切代码；会话库丢失只要求重新无感登录，作品不在服务器。
- [`node:sqlite` 在固定 Node 24 中仍是实验 API] → 只经窄适配器使用并固定/验证生产 Node；仓储契约和 SQL 迁移不依赖其专有扩展，必要时可替换驱动而不迁移产品数据模型。
- [小程序本地文件被系统清理或 AppID 更换] → 明确本地保存语义、周期提示备份、启动校验与救援导出；不承诺自动恢复。
- [长文、版本和依赖超过包体/本地容量] → 不引入大型跨端框架，按需分包，监测主包与用户文件用量，列表索引可重建，达到软阈值时提示备份和清理回收站。
- [RecorderManager 平台分片或中断差异] → 不依赖固定回调大小，严格会话隔离并用当前可用的 Android 真机覆盖授权、后台、耳机/中断和弱网；iOS 设备可用后另行补充兼容性证据。
- [AI 标识规则或平台审核口径变化] → 把标识视为独立能力和提审门槛，在每次正式提交前核对微信与现行法规，不把一次审核结果永久固化。

## Migration Plan

1. 创建共享核心和原生小程序骨架，只接静态夹具；提交安全占位 project config，并用本机 private config 验证开发工具构建，不上传。
2. 实现小程序本地聚合仓储、索引重建、备份与平台适配，先完成普通文字写作和现有 JSON 互导，再接话题、采访和文章会话。
3. 增加最小身份库、微信换码和会话鉴权；在本地使用可替换的 code2Session transport 验证成功/失败，不把 mock 暴露到共享或生产配置。
4. 增加小程序 AI HTTP 与语音 ticket/WSS 路由、Nginx 精确豁免和 RecorderManager 适配；网页原路由继续回归。
5. 更新隐私、AI 标识、部署模板和验收文档。用户把真实 AppSecret 手工写入 `/etc/suiyue-yousheng/runtime.env`，再经单独授权部署服务端和配置临时 AppID 的 request/socket 域名。
6. 使用体验版完成低成本、非敏感的微信换码、一次 AI 和一次短 ASR 联调；记录 Android 的键盘、长按录音、权限拒绝、后台返回、本地恢复和备份。iOS 无可用设备时记录为未验证，不阻塞当前验收，也不冒充通过。
7. 正式 AppID 到位后重新配置本机 private config、服务器 AppID/AppSecret、域名、隐私指引、备案/类目和审核材料；临时数据仅通过显式 JSON 导入副本迁移。上传、提审和发布再次取得明确授权。

回滚时先恢复 Nginx 与上一 release；身份数据库和备份保留在 `/var/lib`，不随代码回滚删除。小程序尚未发布时只需停止使用体验版；已产生的本地文章由用户自行保留或导出，不通过服务端回收。

## 统一会话适配（2026-09-06）
