## Context

仓库含原生小程序、React/Vinext H5 试验端、同一网页工程中的内部话题管理台、共享核心和 Fastify 网关。主文档与 OpenSpec 上下文仍把 H5 当主产品，历史验收与活跃要求混杂。

## Goals / Non-Goals

目标：新会话从 README、AGENTS 入口与 OpenSpec 生成上下文能确定唯一用户端；历史可查，待办不再要求双端产品对齐。
非目标：关闭线上 H5、撤销访问保护、变更后端 API、账号/同步实现、清理浏览器或小程序作品。

## Decisions

- 新建客户端范围规范与维护矩阵，明确用户小程序和内部网页管理台不是同一个产品端。
- H5 专属验收文档移动至 docs/archive/h5；原路径留简短归档指引，避免旧链接与外部引用失效。主文档混合内容先保留历史快照，再改为小程序优先的现行说明。
- 用户追加确认必须切断依赖：H5 独有源码物理移动至 archive/h5，旧共享兼容入口随之归档。服务、管理台、保留测试直接导入 packages/core；后台有独立基础样式，根路由转入后台。归档不作为独立 npm 项目，不安装、编译、加载或发布其内容。
- 旧规范保留共享业务约束；浏览器专属条款标为历史兼容，不作为新小程序需求或门槛。活跃任务直接改写剩余范围；已完成证据不伪造、不倒改。
- check/build/CI 只覆盖活跃小程序、共享核心、后端和管理台；H5 专属 UI/IndexedDB/浏览器采音测试随源码归档，共享协议和网关测试保留。新增依赖边界回归禁止活跃代码引用归档或旧 H5 层。
- 云端账号与跨设备同步仍未实现，后续仅面向小程序；旧 H5 JSON 可以用户主动导入副本，不做 H5 账号绑定或实时同步。

## Risks / Trade-offs

- [归档代码被误编译] → 类型与 Lint 排除归档，限定测试入口，构建与边界扫描验证。
- [只加顶部说明、正文仍冲突] → 重写主要入口、修订活跃条款与待办，历史全文移至归档并保留链接。
- [归档 H5 顺带误伤管理台/服务] → 提前直连共享核心，补后台独立样式，执行完整 check/build、后台浏览器回归；服务兼容 API 不改。

## Migration Plan

仅本地工程迁移；检查本地链接、严格 OpenSpec、完整 check/build 与后台浏览器，完成后同步范围规范并归档本变更。无线上迁移，原始历史保留在归档和 Git；其他活跃变更的真实剩余任务不归档。
