## Context

上一变更为 `Dialog` 增加了 `headerActions`，并仅在 `page === 'chat'` 时显示“查看修改记录”。文章优化首页仍在 `.article-assistant` 内容区渲染 `.ai-record-entry` 整行按钮，造成截图所示的额外高度，也与会话页的导航位置不一致。

## Goals / Non-Goals

**Goals:**

- 让文章优化首页和会话页通过同一个页头操作进入修改记录。
- 删除优化首页内容区整行记录入口和对应废弃样式。
- 保持48px触控目标、完整可访问名称和既有返回/关闭来源语义。

**Non-Goals:**

- 不改变修改记录内容、版本恢复、会话入口或优化卡片。
- 不改变文章 AI、语音、存储、备份或服务端协议。

## Decisions

### 复用现有 Dialog 页头操作

把 `headerActions` 条件从仅 chat 扩展为 menu 或 chat，并复用同一个 book 图标按钮和 `setPage('history')` 路径。相比在优化首页增加小文字链接或缩小整行按钮，页头属于全页级导航，位置更稳定，也已经过360–430px验证。

### 删除而不是隐藏内容入口

从 JSX 移除 `.ai-record-entry` 并删除其样式，不保留不可见副本或重复语义节点。自动化同时断言优化菜单内容区没有该按钮，避免以后再次出现两个入口。

## Risks / Trade-offs

- [图标含义不如文字直接] → 保留 book 图标、48px触控面积和“查看修改记录”完整无障碍名称；与会话页形成一致位置记忆。
- [页头同时含修改记录和关闭] → 现有 `.sheet-header-actions` 已支持两个48px按钮，继续在360、390、430px检查标题收缩与横向溢出。

## Migration Plan

无数据迁移。前端回退即可恢复旧整行入口，修改记录数据和导航目标不变。
