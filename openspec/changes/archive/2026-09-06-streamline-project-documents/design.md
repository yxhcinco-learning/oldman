## Context

维护文档顶层有 34 份，其中 14 份只是已归档跳转；已完成证据和长期规范混排。上一轮事实同步已完成，本轮只优化组织与维护成本。

## Goals / Non-Goals

- 目标：顶层约 10 份职责清晰的文档；证据可追溯、引用不断链、访谈行为覆盖不减少。
- 非目标：不修改运行逻辑、UI、数据、付费联调、部署或第二阶段功能；不清理私有临时备份，不移除有效脚本。

## Decisions

- 使用既有 docs/archive/phase-one 存放阶段证据，而不新增一套分类体系或永久清理报告。重名 CLEANUP 改为 CLEANUP-BASELINE-20260906，旧原文不覆盖。
- 移除 14 份跳转空壳，修正仓库内引用；外部旧文件书签可能失效，可通过 Git 和归档索引查回，不为未知书签长期维护空文件。
- PRODUCT 承载产品与维护范围，ARCHITECTURE 承载模块及模式/轮次/正文三状态，STATUS 只承载阶段状态，DEPLOYMENT 承载准确线上版本，DEVELOPMENT 承载操作命令。证据日期和当时版本仍在原始验收中保留，不视为重复维护源。
- article-ai-session 移出两条访谈要求；独有场景并入 xiaowen-conversation-modes 的连续会话、语义交互、结束整理要求。设计规范继续负责视觉规则，不把全部小文规格合成巨型文档。
- 当前文档检查全部本地文件引用；历史文档仅检查 Markdown 文档引用，不检查已退役代码和临时截图。用负例测试防止校验器空跑。

## Risks / Trade-offs

- 移动产生相对路径失效 → 根据原位置解析再从新位置生成相对链接，含历史引用；增加回归。
- 精简丢掉行为或历史事实 → 完整保留证据正文；逐场景映射访谈条款，仅合并所有权。
- 清理被误读为已上线 → STATUS 明确本轮未部署，线上版本只查 DEPLOYMENT。

## Migration Plan

先写增量规范，再归档/合并文档、调整引用和检查。通过完整 check/build 与 OpenSpec 后本地提交；同步增量规范并归档本变更。恢复仅需 Git 中原文件，不涉及用户数据迁移或线上回滚。
