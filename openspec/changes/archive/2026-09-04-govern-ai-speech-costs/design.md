## Context

当前网关已经限制文章 AI 的单次正文/上下文、输出 token、并发、分钟频率与超时，话题 AI 限制为单管理员并发一且不自动重试，语音限制并发、五分钟和音频字节。`OperationMonitor` 只在进程内累计已返回的 token；它故意不跨重启，也没有语音计费时长，因此只能回答运行状态，不能充当费用保险。

DeepSeek 按实际输入/输出 token 计费，价格还受缓存、峰谷时段和厂商调价影响；Responses 的服务端搜索可增加输入 token，且当前兼容层忽略 `max_tool_calls`。腾讯实时语音按识别时长、最低到秒计费，资源包和后付费状态由腾讯控制台决定。应用必须在调用前保守约束最大风险，但不得把本地估算称作账单，也不得为了计费保存作品、声音或用户轨迹。

## Goals / Non-Goals

**Goals:**

- 对文章 AI、话题 AI、网页语音和小程序语音施加跨重启的上海自然日硬上限。
- 在访问外部服务之前原子预留最坏情况下的用量，完成后按供应商返回用量或实际会话时长结算。
- 以独立 SQLite 保存最小匿名日汇总，并纳入既有部署备份、恢复与 schema 上限检查。
- 在独立后台显示今日用量、预留、剩余、重置时间和可选费用估算，同时保持现有隐私边界。
- 配置或账本不可用时只关闭付费能力，本地写作、备份、话题读取和后台非 AI 操作继续可用。

**Non-Goals:**

- 不读取 DeepSeek 或腾讯云账单、余额、资源包余量，也不自动充值、购买或切换后付费。
- 不提供按用户、IP、作品或话题的配额、排行榜、行为分析或长期请求明细。
- 不承诺本地估算与云厂商最终结算完全一致；退款、缓存、峰谷、赠送额度和阶梯价由控制台核对。
- 不改变模型、语音引擎、用户作品数据库、文章会话格式或小程序发布状态。
- 本轮不连接或更新受控服务器。

## Decisions

### 1. 使用独立 `usage.sqlite`，不复用话题或身份库

开发默认路径为 `.data/usage.sqlite`；生产必须显式配置绝对路径 `/var/lib/suiyue-yousheng/usage.sqlite`。schema v1 使用 WAL、外键、STRICT 表、FULL synchronous、事务、`quick_check` 和未来版本拒绝。日汇总表仅保存上海日期及五个整数累计：文章输入/输出 token、话题输入/输出 token、语音秒数；活动预留表只保存随机预留 ID、日期、服务和预留单位。

不复用 `topics.sqlite`，因为话题库故障不能使文章 AI 或语音依赖话题模块；不复用 `auth.sqlite`，因为网页文章 AI 没有小程序身份配置。JSON 文件无法可靠完成多路请求的原子比较与结算，进程内计数又可由重启绕过，因此均不采用。

### 2. 预算使用用量单位，价格只作可选估算

环境变量分别配置 `ARTICLE_AI_DAILY_TOKEN_LIMIT`、`TOPIC_AI_DAILY_TOKEN_LIMIT` 和 `ASR_DAILY_SECONDS_LIMIT`；值为零是显式停用开关，正整数为每日上限。开发模板提供保守默认值 1,000,000、1,100,000 和 7,200，生产部署仍要求显式存在并通过范围校验。

可选 `DEEPSEEK_ESTIMATED_INPUT_CNY_PER_MILLION`、`DEEPSEEK_ESTIMATED_OUTPUT_CNY_PER_MILLION` 与 `TENCENT_ASR_ESTIMATED_CNY_PER_HOUR` 只用于后台估算。任一价格缺失时仍执行用量硬上限，但相应费用显示“未配置估算”；页面明确供应商控制台才是账单依据。这样避免把会变动的峰谷、缓存和阶梯价格固化为业务规则。

### 3. 先原子预留，再结算实际用量

预算守卫在 SQLite `BEGIN IMMEDIATE` 事务中读取当天已消费与活动预留；只有 `消费 + 预留 + 本次上界 <= 日限额` 才插入预留并允许调用。正常完成时同一事务删除预留并把供应商 `usage` 写入日汇总；实际用量缺失、请求可能已到达上游后的错误、超时或取消，保守地把整份预留转为已消费。能够确定尚未创建外部请求的本地失败才释放预留。

网关启动时把上次崩溃遗留的活动预留按全额计入原日期并清空预留表；这会高估而不会因重启低估或重新获得额度。旧日只保留日汇总，不保存请求时间或预留明细；实现可有界清理 400 天以前的汇总。

### 4. 为不同外部协议选择可证明的保守上界

- 文章 AI：在最终请求 JSON 建好后，以 UTF-8 字节数加固定协议余量作为输入 token 上界，以本次 `max_tokens` 作为输出上界。该上界和现有请求体/上下文限制共同使用；并发请求分别占用预留。
- 话题 AI：关闭搜索时使用请求字节上界加 6,000 输出；开启搜索时因服务端搜索可扩展上下文且 `max_tool_calls` 被忽略，固定预留模型 1,000,000 上下文加 6,000 输出。话题生成已有全局并发一，结算后立即释放未用部分。
- 实时语音：连接腾讯前预留最多 300 秒；当天不足 300 秒时只授予剩余秒数并把该值作为本会话强制计时器。完成、取消或网络错误后按从上游创建到释放的向上取整秒数结算，至少一秒且不超过预留。

无法保证厂商内部计费细节与本地观察完全一致，因此“硬上限”指本应用允许发出的保守最大用量，而非厂商账单金额上限。运维仍应在腾讯云关闭不需要的后付费并在供应商控制台设置可用的账户级告警。

### 5. 共享守卫接入三条路径，错误保持可恢复

`CostGuard` 由网关创建并注入文章 AI、话题后台与语音会话。额度不足统一使用固定类别 `daily_budget_exhausted`：HTTP 使用 429，WebSocket 握手使用 429；账本未配置或不可用使用 `cost_governance_unavailable` 和 503。所有拒绝都发生在 `fetch`、腾讯签名连接或候选创建之前；话题生成仍留下固定失败记录，编辑引子保留在页面，可稍后重试或手工建稿。

公开 AI/语音 status 根据凭据与预算守卫共同报告当前可用，健康接口只增加 `costGovernanceConfigured` 布尔值。后台监控 API 在既有管理员会话后返回独立 `costGovernance` 快照；进程指标仍明确重启清零，用量卡则明确跨重启。

### 6. 部署把用量库视为第三份 release 外状态

激活前停止网关，依次检查并备份 `auth.sqlite`、`topics.sqlite` 和 `usage.sqlite`；启动失败时三库各自隔离失败态并恢复同轮备份。健康检查要求成本治理配置为真并在启动后重新检查 schema v1。普通回滚只检查兼容性，不恢复或删除用量，以免重新获得已消费额度。

## Risks / Trade-offs

- [保守预留可能过早拒绝，特别是联网话题生成] → 话题后台本就低频且并发一；完成后立即退还未使用预留，额度不足时手工草稿始终可用。
- [崩溃会把未完成预留全额计入] → 这是阻止通过重启绕过预算的安全取舍；额度在下一上海自然日自动恢复，不提供危险的后台清零按钮。
- [供应商返回 token 缺失或实际量超过推导上界] → 缺失按全额预留结算；异常超界记录实际值并阻止当天后续请求，测试覆盖该降级，但无法撤销已经产生的厂商费用。
- [SQLite 写失败会影响全部付费能力] → 失败关闭只作用于 AI/语音，并返回可恢复提示；本地作品和只读内容不依赖账本。
- [费用估算与账单不一致] → 估算单价必须由运维显式配置并在 UI 标为估算，正式核算只看供应商控制台。

## Migration Plan

1. 新增 OpenSpec 与 `usage.sqlite` schema/运行时，先以本地临时库验证空库、重复启动、旧版本拒绝、并发预留、崩溃结算和日期切换。
2. 将守卫注入文章 AI、话题 AI 和两条语音入口，使用上游替身验证额度内、耗尽、失败、取消与账本不可用；普通测试不读取真实密钥。
3. 扩展管理员监控 API/UI、健康布尔值和文档，在桌面与手机尺寸验证。
4. 更新 `.env.example` 与部署模板，并演练三库备份/恢复；本地 `npm run check`、`npm run build` 和严格 OpenSpec 校验通过后归档。
5. 本轮不部署。未来服务器激活前由运维核对上限与估算单价；回滚代码时保留 `usage.sqlite`。
