## Context

见 [proposal.md](proposal.md)。全局 AGENTS 当前为空；项目五个 OpenSpec 技能来自 1.12.0，用户 prompts 目录还保留较旧的四个 opsx 流程。个人技能与厂商插件分属不同维护来源。

## Goals / Non-Goals

让范围和完成条件决定是否继续，使本次请求能够跨提案、实施和验收完成。保留讨论只读、真实权限、数据恢复、费用及代码门禁。厂商工具契约与本机执行权限不作为提示词优化对象。

## Decisions

- 通用偏好放用户全局 AGENTS，项目规则只保留仓库差异；不将官方指南整段复制到所有技能。
- 项目技能直接修改有问题的条款，保留路径、依赖闭包、规则快照及同步后才能归档的要求。旧 opsx 提示改为当前可用技能入口，避免两套流程漂移。
- 多模式个人技能收窄触发条件、按需读资料；既有资源和输出质量约束保留。厂商缓存仅审计，不直接改写会被升级覆盖的副本。
- `docs/STATUS.md` 与 `openspec/config.yaml` 的开工提示按任务路由，避免指令维护被重定向到文章发表真机待办。
- 本机原文件逐项备份，项目文件由 Git 保留；本次只改指令、规范和记录，运行文档、OpenSpec、技能结构与行为场景验证，不运行应用构建或计费联调。

## Risks / Trade-offs

- 技能生成器升级可能覆盖本地调整 → 在开发说明中标明升级后核对这些授权和收尾条款。
- 静态检查不能证明未来模型表现 → 单列场景审查与未进行的真实任务验证，不宣称性能提升。
- 文件落盘不等于当前任务已注入内容被替换 → 交付区分后续加载生效与本轮按用户授权采用；不改应用内置提示或权限配置。

## Migration Plan

完成检查后本地提交并同步本次增量规范、归档。恢复时对照本次提交反向恢复仓库文件；全局文件从本机备份逐项恢复并保留期间新修改，不批量覆盖其他文件。
