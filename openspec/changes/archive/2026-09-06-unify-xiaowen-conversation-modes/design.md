> 2026-09-06 用户修订：小程序唯一用户端，网页仅运营后台；H5 源码与专属验收归档并切断依赖。下文已完成阶段保留历史事实，剩余任务按此范围执行。退役 H5 不代表共享/小程序缺陷或新 AppID 验收完成。

## Context

访谈目前在小程序中按题库推进，网页按独立素材重建消息。已有文章会话、候选确认、版本和持久化能力可以复用，但必须统一消息和模式。

## Goals / Non-Goals

目标：连续会话、持久模式、同次请求语义切换、原始消息与素材分离、结束整理、小程序两种展示一致。非目标：跨作品记忆、后台主动采访、发布、新模型或外部服务。

## Decisions

- 收尾真实联调发现短材料整理虽通过协议/模式断言，仍可能补造伤情与心理。对话成文改为明确“先逐句核对来源、短材料短成文”，区分未获回答的助手追问和用户事实；固定联调加入已观测虚构细节拒绝断言，并保留人工语义比对，不能把提示词或有限词表宣称为通用事实验证器。

- 3.3 真机反馈修订：小文和访谈长按转写提示独立于三列输入行，按住/连接/录音/收尾保持麦克风原位，不用颜色替代操作说明。对话与正文待确认语音隔离：仅 dialogue 不受旧正文编辑拦截，未确认内容不进上下文；采用仍须先处理待确认正文。两页录音会话测试和录音中布局纳入回归。

- 可靠性收尾：已收到的小文结算先保存每篇作品独立的结果恢复记录，再写聚合；写入失败保留内存副本及已落盘恢复记录，页面提供“重试保存／救援导出”，不退回计费请求重试。恢复记录携带预期 revision；冲突不覆盖新正文。重开读取恢复记录，但必须明确保存后才发布模式变化和结果。写入介质完全不可用时如实说明仅内存保留，不能承诺进程被杀后零丢失。
- 历史恢复复用文章预览：选择记录只查看，显式“恢复这版”并确认后追加 restore 版本，保存当前手改快照并校验查看时正文/预期 revision；撤销记录单独关联恢复版本，保留曾采用的 AI 来源，撤回后不再提供同条撤销。

- 无话题时不渲染空绿色主题背景、书本图标或占位题目，仅保留纸面单行访谈操作；空会话提供轻量问候展示，不写入素材、不触发模型。无话题首次访谈使用通用介绍并先澄清想聊什么；只有实际正文/素材存在时才承接已有内容，不能以消息非空（如仅问候）判断已深入交流。小程序结束等待期间也按持久mode显示开启入口（禁用），不再显示旧结束状态；控制操作不清空未发送输入。

- 顶部主题区改为与页头相接的通栏浅绿区域，无外边距和圆角；访谈中两行紧凑排列，结束后合为单行主题和“开启访谈”，删除闲聊状态占行。长题仍按实际剩余宽度滚动。已采用结果中的“看看文章”和图标文字“撤销”始终同排，主次有别、各保留至少48px触控高度，不改变撤销确认和版本规则。

- 文章结果展示使用用户语言：消息内“看看文章”为浅绿圆角主入口，不重复赭色核对标签；预览去除品牌/本机说明的重复层级和整理说明卡片。短标题、轻量 AI 提醒、状态/对照、独立滚动正文、固定决策区五层，不更改原始模型回复与备份，仅展示层转换旧“查看候选”指引。

- 顶部为固定浅绿主题区，单行超长话题按实际宽度往返滚动；访谈中下行显示状态与结束操作，结束后开启操作与主题同排，均使用细下划线；底部发送原位提供停止，等待只显示紧凑三点，不使用滑动开关。共享 conversationView 根据 running/failed/cancelled turn 派生助手占位，采用正式 a-turnId 作为稳定展示键；不持久化临时气泡。失败、取消、重试和结果共用回复位置，存储失败仍保留独立补救。

- 2026-09-06 用户修订：访谈只作为会话开关，取消普通对话分类标签；固定话题与紧凑操作行，换题在当前助手气泡内，不重复聊天 AI 提示。模型实测将候选放在 dialogue.body，服务端只对唯一错位字段归一化，再严格校验，双字段冲突拒绝。

- ArticleSession 增加可兼容缺省的 conversation，保存 mode 与连续事件；老数据按稳定 ID 恢复，未知顺序保留来源顺序不伪造时间。新会话以 conversation.mode 为唯一模式来源。
- 新增 dialogue action 与 protocolVersion=2；输入包含 mode、messages、command（send/start/finish/change/confirm-edit）及用户原文。旧 action 原样兼容。共享纯函数负责准备与结算，平台控制器继续负责事务和网络。
- 模型同次返回 reply/start/finish/confirm-edit/edit 意图、素材原文片段及更正引用。语义不明确保持模式并澄清。模型结果只关联用户原文，不把生成文本冒充素材。
- 按钮开启仅持久化模式和静态开场；结束先持久化普通模式与事件，再请求候选。自然语言切换在有效响应落库时生效。用户明确结束只有整理路径，没有不整理选项。
- 访谈改文先确认结束并继续修改；确认携带原要求，同次整理/改文生成候选。取消确认保持访谈。
- 收起不改模式、不请求；打开恢复会话。访谈只允许回应和追问，结束才允许候选。候选继续显式采用。
- JSON v5 与本地可选字段惰性升级，导入副本重映射关联。保留旧版本与 AI 披露。新协议不受旧 2000 字 prompt 限制，统一用户消息最多12000字，总上下文继续120000字符。

## Risks / Trade-offs

- 语义判断出错 → 结构化契约、来源校验、同一套用例及有限真实效果验证；正文永不自动采用。
- 保存与异步响应竞态 → 沿用串行事务、请求 ID 校验，消息与模式同事务结算；失败保留重试状态。
- 旧消息顺序不完整 → 保留原来源和稳定 ID，不推断无法证明的时间。

## Migration Plan

先实现规范与核心，再协议和两端；备份 v1–v4 可读，v5 显式携带新状态。发布另行执行，未来发布应先更新兼容新旧请求的服务端，再更新客户端；回滚前导出 v5，旧客户端不应打开新格式库。


## 实施适配

H5 本地库升级 v4、小程序聚合升级 v2；保留旧结构惰性迁移。H5 会话变更延迟到本地写入成功才发布到 UI；小程序准备保存期间即锁住发送，页面重新进入时订阅控制器完成事件。所有平台都复用共享准备/结算函数，旧 action 仅兼容。真实联调发现模型遗漏素材、批量提问后，新增明确素材关联规则、单问题示例及短材料整理要求；后续真实结束结果失败尚需定位，见验收记录。
