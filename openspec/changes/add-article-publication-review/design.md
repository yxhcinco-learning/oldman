## Context

现有账号库 schema 2 与云作品共用事务；管理员认证在话题后台内，缺少公开用户文章模型。小程序正文聚合 v3 和 JSON v6 已稳定。已确认范围见 proposal.md。

## Goals / Non-Goals

目标是保留私有同步边界并实现真实发表、审核、好友阅读闭环。不恢复 H5、不引入第四数据库或外部存储服务；不增加自动审核。

## Decisions

- 账号库 schema 3 一次迁移新增 username_claims 与发表域表，昵称规范化采用 NFKC、trim 和小写比较；以账号创建时间和 ID 排序迁移，先保留全部合法旧名，再给空名/重复名分配不冲突数字后缀。名字归属永不转移。
- 发表存储独立于 WorkSnapshot：文章记录维护稳定公开 ID、状态版本、当前公开和待审引用；投稿只存 title/body/authorName/aiAssisted/coverAssetId、来源云版本及设置版本。读写服务以白名单投影返回，不给管理员通用私有查询接口。
- 客户端发表前同步并取得服务器预览。提交传 operationId、workVersion、settingsVersion、authorName，服务端在账号事务重算预览并校验；返回丢失持久化同操作重试。管理审核同样用 operationId 和 expectedVersion。
- 图片用 sharp 处理成去元数据主图和两种裁切图，分别预览 1:1 与 5:4。输入最多 8MiB/40MP，主图长边 2048；图片及快照计入独立 100MiB 配额。BLOB 与引用同库方便事务删除和现有备份；替代外部对象存储避免新增服务。异步图片解码后提交前重新鉴权和校验版本。
- 本机独立发表侧文件保存原图路径、裁切范围、服务器设置基线和待处理操作，使用账号空间、串行及临时文件替换；二进制图片扩展文件适配器。服务器设置与正文云版本分开，断网先保存本机，冲突需刷新设置而非覆盖。
- 私有作品 trash/purge 在原事务直接撤销投稿及公开版；restore 保持未发表。审核旧请求按版本失败。纯审计和回执不携带正文，purge 后清除投稿及独占资源。
- 导航增加公共 articles Tab，works 变普通页面；新增 publish 和 article 页面。用户名编辑组件复用个人资料逻辑。公共图片鉴权下载为本机文件，好友分享只使用服务器确认的当前公开版，不以截图回退。
- 阅读和分享目标使用稳定 articleId；公开列表首次发表时间倒序、20 条游标分页。下架后所有公开读取拒绝，微信历史卡片缓存不在应用控制范围。

## Risks / Trade-offs

- 存量数据迁移或旧网关误读 → 事务迁移、真实 schema 2 夹具、兼容上限和备份检查，禁止降级覆盖数据库。
- 会话切换或审核竞态 → 提交事务重新鉴权、固定操作回执及独立状态版本。
- 本机空间不足或选图中断 → 保存正文与旧设置后再替换封面，错误保留重试入口；不承诺未持久化数据可跨进程恢复。
- JSON v6 不包含封面 → 隐私/备份说明明确，导入副本需重新选择图片，避免导入已有公开身份。

## Migration Plan

先完成规范和迁移回归，再实现服务/后台及小程序，完整检查与构建后分阶段本地提交。当前线上 0.2.0 不动。实际部署另需授权，迁移前使用现有三库备份工具，schema 3 不允许用不兼容旧网关或旧库回滚。真机证据未齐保持变更活跃。

2026-09-07 预览反馈后，用户已追加授权更新线上测试服务端。本轮按固定已验证源码独立部署网关及 Nginx 路由，先验证账号库副本迁移与三库备份，保留已有数据；小程序样式修正与实际服务环境分别记录，不把未部署接口当作已确认的空列表。
