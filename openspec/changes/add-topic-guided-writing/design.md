## Context

现有产品以作品列表和空白编辑器为入口，小文主要在用户已经有正文后回答、修改或整理。新的产品方向面向有文化表达意愿的退休知识人群：用经过筛选的当下事件、周期主题和慢议题降低启动成本，再让用户选择自由写作或由小文逐问引导。议题需要联网发布，但作品、原始表达、采访素材和 AI 候选仍须保持可追溯，不能把新闻摘要或模型补写静默当成用户正文。

这项变化同时涉及内容运营、服务端议题数据、作品模型、编辑器信息架构和文章 AI 协议。第一阶段的目标是验证“议题能否促成真实写作”，而不是建设新闻门户或开放社区。

## Goals / Non-Goals

**Goals:**

- 为目标人群提供少量、可信、可直接转入写作的议题，而不是无限消费型信息流。
- 让同一议题支持“正常写作”和“小文采访”两条平行、可随时切换的路径。
- 用单一小文角色承载采访，避免恢复一个职责含混且与小文重复的通用聊天入口。
- 在数据和界面中区分来源事实、AI 加工、用户观点、采访素材与已确认正文。
- 让议题、素材、正文和候选在失败、刷新、导出与恢复后仍可核对。

**Non-Goals:**

- 不做分钟级新闻、热搜搬运、无限推荐流或无人审核的自动发布。
- 不做第二个助手、开放域闲聊、后台主动采访或自动把回答写成文章。
- 不做公开评论区、关注关系、开放投稿社区、自动发布到外部平台或正式账号体系。
- 不在本变更中决定长期商业模式、完整兴趣画像或跨设备作品云同步。

## Decisions

### 小文是角色，采访是工作模式

不恢复与“小文”并列的“聊天”工具。话题页提供“自己写”和“和小文聊聊”两个动作；后者进入同一篇作品、同一个小文会话中的采访模式。用户面对的是一个伙伴和两种工作方式，而不是两个相似的对话产品。

采访模式使用明确状态和请求动作，而不靠自由输入关键词猜测。小文每轮只提出一个基于议题背景、用户已确认职业经历或前序回答的问题；问题响应不得携带候选正文。用户回答保存为采访素材，随时可返回编辑器，返回不代表结束、丢弃或成文。

相比把采访重新命名为通用聊天，这一方案保留了原聊天构想中“通过引导帮助输出”的价值，同时给自由问答、采访和文章修改建立清楚边界。

### 议题在前台是内容，不是写作任务

“为什么值得写”“可以从这里想起”“看看背景与角度”等措辞属于编辑筛选和产品流程，不直接展示给用户。正式界面把议题包装为“热门话题”：先给出发生了什么、相关切面和可核对来源，用户是否联想到自己的经验由阅读自然触发。内部 `whyItMatters`、角度和起始问题仍可服务审核与小文上下文，但前台不得使用“值得写”“建议你写”“从这里写”等布置任务的口吻。

“热门”“文章”“我的”使用同一首页壳层中的固定底部导航，以“热门”作为默认首屏，不在内容区顶部重复页签，也不在一条长页面中连续堆叠作品列表与五张话题卡。底栏用克制图标、文字和当前态共同表达三个稳定目的地，而不是只排列三个文字按钮。切换页面不改变作品、草稿或议题加载状态；“文章”页把明确的无箭头“开始写作”固定在主导航上方，与作品列表滚动分离，确保作品再多也始终可见；“热门”通过内容卡进入写作，“我的”一期只提供真实的作品与备份入口和本机保存说明，不制造尚不存在的账号体系。

### 采访使用单线程聊天而不是问卷表单

采访页沿用小文的消息流和固定输入区：已回答内容显示为用户消息，当前问题显示为小文消息；用户通过文字或语音输入后点击一个“发送”动作，系统先保存本轮回答，再请求下一问。界面不常驻“保存回答 / 继续问我 / 先暂停 / 回到文章”等重复控制，也不把所有素材做成默认可勾选表单。

“换个问题”只附着在当前小文问题旁，并与问题文字使用同一左侧起点，不因默认按钮内边距显得额外缩进；存在回答后才提供一个次级“整理成文章”动作。关闭小文即暂停并回到文章，重开继续当前采访；显式整理仍沿用候选预览和确认边界。这样每一时刻只有一个主要动作，同时保留换题、暂停和成文能力。

### 两条路径汇入同一作品

话题不是必须经过的向导。选择“自己写”后立即进入正常编辑器，事件背景作为可收起的参考面板存在；用户可以不采用任何相关切面，也可以以后再进入采访。选择采访后生成的素材与同一作品关联，切回正常写作时正文保持原样。

两条路径共享作品 ID、议题快照、版本和小文会话，但正文、采访素材和 AI 候选使用独立字段或存储记录。这样模式切换是展示和流程变化，不是内容搬运。

### 议题使用已发布快照而不是实时开放网页上下文

服务端发布 `Topic`，包含稳定 ID、修订号、事实摘要、来源标题/URL/发布时间、议题更新时间、写作角度、起始问题、标签和有效状态。作品开始写作时保存必要的 `TopicSnapshot`，保证以后能知道文章当时依据什么背景；若服务端已有更新，界面提示有新版本，由用户选择查看，不静默改写作品背景。

第一阶段由人工选择信息源，AI 只生成待审核的摘要、角度和问题，审核通过后才进入正式议题接口。来源只保存必要元数据和合规短摘要，不复制整篇受版权保护的内容。相比每次写作时临时搜索开放网络，该方案更可核对、可测试，也能控制错误和内容成本。

### 将事实、观点、素材与候选分层

领域层至少表达四类来源：`topic-source`、`user-note`、`interview-answer` 和 `ai-candidate`。议题摘要只能作为背景；用户在采访中的回答是原始素材；小文整理出的全文仍是候选。系统不得因为用户切换模式或结束采访而自动把任一背景或候选追加到正文。

用户点击“整理成文章”后，服务端以议题快照、被选择的采访素材和当前正文生成完整候选，同时列明使用了哪些来源事实和用户材料。候选继续经过全文预览、基准检查与明确应用；事实性陈述需要能够回指议题来源或标为用户观点，无法核对的内容以问题提示而非补写。

### 内容服务与本机作品先保持分离

议题目录和详情由只读服务端接口提供，可以公开缓存；作品、采访素材和小文会话第一阶段继续本机保存。这样无需先引入账号和云端作品就能验证核心闭环。已进入作品的议题快照可在内容接口暂时不可用时查看，网络失败不得阻止用户继续编辑已有作品。

### 先验证编辑判断，再自动化采集

首批使用少量人工制作议题卡验证三件事：目标用户是否愿意开始写、采访是否增加用户原创材料、正常模式是否仍被需要。确认后再实现自动采集、去重、事件聚类和审核队列；自动化只减少编辑劳动，不取消发布审核。

## Risks / Trade-offs

- [用户只看话题不写，产品退化为资讯站] → 每日数量受限，话题详情以简短背景、相关切面和两个自然入口为主，试点重点衡量从话题到有效输入、成稿与再次写作，而非阅读时长。
- [采访与现有小文自由对话再次混淆] → 采访使用显式进入/退出状态、单问题契约和素材区；不新增第二个头像、会话或通用聊天入口。
- [问题过多让用户感到被审问] → 一次只问一个，回答后自然进入下一问；“换个问题”贴近当前问题，关闭即暂停，不自动追问敏感或被跳过的内容。
- [实时事件事实变化或来源出错] → 保存修订和更新时间，保留来源链接，发布端支持更正；已有作品只提示更新，不静默替换。
- [AI 把资料或推断写成用户观点] → 分层上下文、候选确认和来源说明共同约束；事实无法核对时必须提示，不自动补齐。
- [新增云端内容破坏本地优先认知] → 明确议题来自网络、作品仍按当前存储边界保存；内容失败与本地写作解耦。
- [内容审核和版权成本被低估] → MVP 控制每日数量、来源集合和摘要长度；验证成立前不建设大规模抓取。

## Migration Plan

1. 先用人工议题卡和目标用户试点验证内容类别、两个入口名称及成文路径，记录只阅读不写、退出采访和来源信任问题。
2. 增加只读议题接口与审核发布数据，保持作品功能不依赖议题服务可用。
3. 以非破坏升级增加议题快照和采访素材存储；旧作品没有相关字段时继续按普通作品打开。
4. 上线正常写作背景面板，再上线小文采访和显式成文；每阶段分别验证保存、恢复、备份和事实来源。
5. 回滚时隐藏议题入口和采访模式，不删除已保存正文、素材或快照；新版备份继续保留新增数据，旧版导入规则需明确拒绝或安全忽略。

## Open Questions

- 首批是否进一步聚焦退休教师，以及首批议题的三到五个稳定栏目是什么。
- “和小文聊聊”在目标用户试用中是否仍有审问感，是否需要进一步弱化采访流程感。
- 第一阶段允许哪些信息源、怎样取得摘要和展示链接的许可。
- 采访素材默认全部参与成文，还是由用户在成文前逐条选择。
- 事实来源在最终文章中采用文末来源、段落标记还是仅在编辑器内核对。
