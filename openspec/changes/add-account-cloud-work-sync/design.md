## Context
用户已确认主动微信登录、登录后自动入云、单点登录及完整写作现场。现有 auth.sqlite schema 1、聚合 schema 2、备份 v5；服务端不保存作品，客户端遇到 401 会自动登录。

## Goals / Non-Goals
目标：真实账号与资料、事务性私有作品 API、耐重试同步、跨设备续写与可救援的离线输入。
非目标：多人合并、H5、手机号、密码、设备列表、账号注销、新增云服务、自动上线。

## Decisions
- auth.sqlite schema 2 增加账号资料、会话种类/撤销原因、云作品、幂等操作。共用同步 SQLite 事务，在提交作品时重新认证，避免鉴权与接管之间的竞态；不用客户端 userId 授权。
- 新 /api/mini/account/login 只由主动操作触发。账号会话沿用随机散列 token、30 天有效期；续期只延长当前会话。登录撤销该用户所有旧会话，启用账号后旧换码端点拒绝重新签发。失效必须点击登录。
- 资料更新同时接受 PATCH 和 PUT，小程序 wx.request 使用 PUT；昵称可选、最多 32 字；头像输入最多 2MiB，sharp 限制像素、解码为 256px JPEG，移除元数据，只存转换后数据，鉴权读取。
- WorkSnapshot 包括 Work、ArticleSession、WritingState（未发送小文输入与来源）。本机 revision 不充当云版本；云端每篇 version 与账号 change sequence 单调递增。使用固定 operationId 和 baseVersion，保存内容与幂等回执事务提交，永久删除只留 tombstone。
- 小程序仓储按游客与服务端确认的 accountId 分目录，服务实例绑定固定目录；更换账号不改变旧实例目标。采用持久认领记录迁移游客作品，先写固定归属与目标 ID 的认领意图，再复制账号空间并标记完成，重复启动不会重复上传或归入另一账号。
- 聚合 schema 3 增加写作状态与同步元数据。待上传操作和 payload 冻结写入聚合，后续本地修改保留 dirty；ACK 仅清除对应操作，不能把新输入误标已同步。
- 本地写入沿用 700ms 防抖；同步串行合并尚未发送的修改，上传只在本地提交后触发；网络恢复、前台返回、打开云作品先刷新会话与远端。前台 30 秒检查有效会话，后台停止轮询。
- 本机未上传修改与远端版本不同：在同账号空间持久保留恢复副本（不自动入云），再落盘远端；用户可查看/导出/另存新篇。不做正文自动合并。
- 云作品断网后暂停修改，但先保存已收到输入；新建本机草稿可以写。删除/恢复/永久删除云作品均需在线且使用最新版本。
- JSON v6 包含 writingStates，v1–v5 缺省为空输入；导入复制并重映射引用，身份与同步元数据不导出。备份每卷最多 10MiB，完整云备份先拉全，离线只导出本机缓存。
- 默认单篇快照 8MiB、账号 100MiB、1000 篇（含回收站）、每账号每分钟 120 请求，均可配置；超限保留本机并提示。
- 现有 Nginx 精确白名单新增账号/作品路径，单独放宽请求体上限，访问日志继续关闭。无需外部存储或云开发。

## Risks / Trade-offs
- 单点登录不能消除未上传草稿 → 服务端版本校验、恢复副本与迟到结果隔离。
- 操作系统中断和磁盘完全不可写 → 保留既有内存救援，不声称零丢失。
- 全快照上传流量大 → 本地防抖、串行合并、大小限额；不引入复杂增量正文协议。
- 原数据库备份包含作品后更敏感 → 继续受限目录/权限，不进日志；在线删除不声称立即抹除离线设备或历史运维备份。

## Migration Plan
先完成规格；实现服务与协议并验证；实现本地迁移/同步和界面；更新运维模板及文档。数据库迁移在接流量前备份并事务执行。正常回滚检查目标支持 schema 2，不降级数据库；服务启动后即禁止自动恢复旧备份覆盖新数据。初始实施范围不执行部署，后续追加授权如下。

2026-09-07 追加授权：用户手机预览提示无法连接云端，并明确要求必要时发布到测试。公网账号/作品接口实测 404，现有网关仍为第一阶段，因此本次补部署第二阶段网关与精确 Nginx 白名单至既有测试服务器；保留运营网页服务和其他项目，复用服务器私有配置。先备份三库和配置，迁移后禁止自动用旧库回滚；不上传、提审或发布微信小程序包。手机继续通过开发者工具预览验证，真机证据另记。

## Open Questions
无待定产品决策。Android/iOS 实际微信登录和双设备验证需要实际设备证据，单列任务；缺证据保持活跃，不冒充完成。

## 手机反馈：开屏、登录与个人中心（2026-09-07）

- 最新用户要求取代原“我的页为主要登录入口”的布局：冷启动短暂品牌开屏，恢复有效会话后进首页；无会话进入独立登录页。微信授权登录按钮主动调用现有换码接口，首次自动建号，不添加密码、手机号或强制头像昵称。按用户最新要求必须登录才可进入热门、作品与个人中心；无会话只开放开屏、登录和隐私页。历史游客文件继续保留供首次登录认领。已有账号遇到临时断网仍按既有本机保存边界使用。
- 登录页沿用信纸枝叶插画、森林绿胶囊主按钮和大字号；登录按钮下只保留隐私说明入口，不显示自动云保存与首次自动建号说明，不伪造微信系统授权弹窗。
- 小文、接受采访和语音入口发现需登录时直接进入登录页；跳转前持久保存当前输入。返回上下文只保留应用内路由、固定原账号与作品标识；游客认领后按持久 claim 映射 ID，禁止将原账号作品带入其他账号。登录恢复页面但不自动发送模型请求或录音。移除跳过/取消入口；直接路径、返回栈和重新进入页面均核对登录状态，不允许绕过。
- 登录成功与同步失败分开处理；同步失败保留已登录状态、真实错误及重试同步入口，不再次换码接管。异步登录结果在用户离开登录页后不得强行跳转。
- 个人中心顶部仅保留品牌与“我的”，资料行展示默认叶片头像/真实昵称和编辑入口；正常状态不展示同步行，无常驻“重新同步”。下方以明确的作品、回收站、备份、隐私入口分组，退出登录单独置底并确认。说明只在相关抽屉出现。所有 button 显式约束宽度，避免微信默认按钮宽度造成换行挤压；页头占位避免顶部文案被导航遮挡。
- 正常编辑页不常驻同步状态；需登录时显示“微信登录”，网络/同步失败才显示“重试”，不再显示“请去我的登录”或把登录问题当成重新连接。

## 手机反馈：保存竞态与提示（2026-09-07）

- 仓储的列表加载、索引重建、聚合读取和恢复记录清理与保存/云确认共用串行队列，不能在原子替换的中间状态读取或重建索引。清理已不存在的备份可幂等完成，权限与容量失败仍需上报并保留恢复路径。
- 按用户进一步确认，自动同步是默认后台功能，编辑/会话、作品卡和个人中心不常驻同步、上传或云端保存状态。保存详情只在主动打开备份与恢复后查看；内部继续区分本机与对应云确认，空白稿不虚报保存。仅失败、断网暂停或登录失效时出现必要提示和操作。
- 页面错误使用中文原因和可执行的补救，不直接展示微信文件路径、原始异常或协议校验详情；按钮改为“重试保存 / 导出当前内容”。本机保存失败时不再叠加同源云错误。空作品列表删除过期游客说明；隐私和备份抽屉保留必要事实。
