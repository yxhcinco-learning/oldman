## Context
用户已确认主动微信登录、登录后自动入云、单点登录及完整写作现场。现有 auth.sqlite schema 1、聚合 schema 2、备份 v5；服务端不保存作品，客户端遇到 401 会自动登录。

## Goals / Non-Goals
目标：真实账号与资料、事务性私有作品 API、耐重试同步、跨设备续写与可救援的离线输入。
非目标：多人合并、H5、手机号、密码、设备列表、账号注销、新增云服务、自动上线。

## Decisions
- auth.sqlite schema 2 增加账号资料、会话种类/撤销原因、云作品、幂等操作。共用同步 SQLite 事务，在提交作品时重新认证，避免鉴权与接管之间的竞态；不用客户端 userId 授权。
- 新 /api/mini/account/login 只由主动操作触发。账号会话沿用随机散列 token、30 天有效期；续期只延长当前会话。登录撤销该用户所有旧会话，启用账号后旧换码端点拒绝重新签发。失效必须点击登录。
- 昵称可选、最多 32 字；头像输入最多 2MiB，sharp 限制像素、解码为 256px JPEG，移除元数据，只存转换后数据，鉴权读取。
- WorkSnapshot 包括 Work、ArticleSession、WritingState（未发送小文输入与来源）。本机 revision 不充当云版本；云端每篇 version 与账号 change sequence 单调递增。使用固定 operationId 和 baseVersion，保存内容与幂等回执事务提交，永久删除只留 tombstone。
- 小程序仓储按游客与服务端确认的 accountId 分目录，服务实例绑定固定目录；更换账号不改变旧实例目标。采用持久认领记录迁移游客作品，先写账号空间再标记已认领，重复启动不会重复上传或归入另一账号。
- 聚合 schema 3 增加写作状态与同步元数据。待上传操作和 payload 冻结写入聚合，后续本地修改保留 dirty；ACK 仅清除对应操作，不能把新输入误标已同步。
- 本地写入沿用 700ms 防抖；同步串行合并尚未发送的修改，上传只在本地提交后触发；网络恢复、前台返回、打开云作品先刷新会话与远端。前台 30 秒检查有效会话，后台停止轮询。
- 本机未上传修改与远端版本不同：在同账号空间持久保留恢复副本（不自动入云），再落盘远端；用户可查看/导出/另存新篇。不做正文自动合并。
- 云作品断网后暂停修改，但先保存已收到输入；新建本机草稿可以写。删除/恢复/永久删除云作品均需在线且使用最新版本。
- JSON v6 包含 writingStates，v1–v5 缺省为空输入；导入复制并重映射引用，身份与同步元数据不导出。备份每卷最多 10MiB，完整云备份先拉全，离线只导出本机缓存。
- 默认单篇快照 8MiB、账号 100MiB、1000 篇（含回收站）、每账号每分钟 120 请求，均可配置；超限保留本机并提示。
- 现有 Nginx 精确白名单新增账号/作品路径，单独放宽请求体上限，访问日志继续关闭。无需外部存储或云开发。

## Risks / Trade-offs
- 单点登录不能消除未上传草稿 → 服务端版本校验、恢复副本与迟到结果隔离。
- 操作系统中断和磁盘完全不可写 → 保留既有内存救援，不声称零丢失。
- 全快照上传流量大 → 本地防抖、串行合并、大小限额；不引入复杂增量正文协议。
- 原数据库备份包含作品后更敏感 → 继续受限目录/权限，不进日志；在线删除不声称立即抹除离线设备或历史运维备份。

## Migration Plan
先完成规格；实现服务与协议并验证；实现本地迁移/同步和界面；更新运维模板及文档。数据库迁移在接流量前备份并事务执行。正常回滚检查目标支持 schema 2，不降级数据库；服务启动后即禁止自动恢复旧备份覆盖新数据。本次不执行部署。

## Open Questions
无待定产品决策。Android/iOS 实际微信登录和双设备验证需要实际设备证据，单列任务；缺证据保持活跃，不冒充完成。
