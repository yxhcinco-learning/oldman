## Context

真实编辑器已有串行 IndexedDB 写入和 revision 冲突保护；AI 仍在独立模拟树。用户已确认两种优化、文字追问、预览后应用，并提供 DeepSeek V4 Flash Key。首个受控连通测试 HTTP 200，35 输入 / 5 输出 tokens；不代表功能效果已验收。

## Goals / Non-Goals

**Goals:** 文章级持久上下文、可核查版本、真实优化、显式确认写回、完整失败恢复、沿用 Echoes 和现有工具链。

**Non-Goals:** 自由指令执行改文、语音聊天、精简/扩写/配图、跨设备同步、部署、自动摘要计费循环、向量数据库或 Agent 框架。

## Decisions

- 新增独立 ai 功能模块，不将 demo 中的模拟状态接入真实存储；正式聊天和优化入口切换到同一个文章助手。主卡“常规优化”，两列按需修改按钮，底部小文文字入口；未实现操作禁用并注明待开放。保留旧预览与模拟源码的独立测试。
- 每篇作品有一份 ArticleSession，保存不可变 ArticleVersion 和 AiTurn。版本保存 title/body，标记 baseline/manual/regular/polish/restore；turn 保存动作、基准版本、回答、候选正文、引用及运行/待采用/已采用/放弃/失败/取消状态。未采用候选不冒充当前正文。
- IndexedDB v2 新增 articleSessions store；WorkRepository.save 扩展可选 session，同一事务保存作品、恢复快照和会话。DraftWriter 继续串行并检查 Work.revision。普通自动保存不重复写完整历史。手动输入停顿 1200ms，以及离开编辑、完成段落/语音、发起 AI 前，追加有变化的版本；首次使用只能从已有正文建立基线，不能声称找回接入前已丢失的内容。
- POST /api/ai/turn 接收动作 regular/polish/question、该作品当前版本和选取的历史，返回 answer/body/citedVersionIds。GET /api/ai/status 只报告配置状态。浏览器不能指定 system prompt、Key、模型或上游 URL。使用原 Fastify 3002 与同源 Vite /api/ai 代理，原语音协议不变。
- 服务端原生 fetch 调 DeepSeek Chat Completions，固定官方地址与 deepseek-v4-flash；非思考模式、JSON 输出、120 秒超时、最多 16384 输出 tokens，无自动重试。正文最多 12000 字符、问题 2000 字符、上下文 JSON 最多 120000 字符、HTTP 请求最多 1MiB、响应最多 256KiB。限制同时两次请求与每分钟二十次；取消、断开、关闭服务均终止上游。
- 当前完整正文始终提供；优先给出近期会话/版本，再按问题中文字词匹配选择旧版本。本机历史不自动删除；超过上下文预算时明确告知部分旧记录未发送，追问不得把缺乏证据当作事实。返回的版本引用只允许来自实际提供的记录，用户可查看/复制原文与预览恢复。
- regular 只做基础通顺、分段、错别字和标点；polish 改善用词、描写和节奏，二者均保留事实、人物、时间、观点和原意，不擅自新增细节、删减内容或改变文体。标题只作上下文，不自动改标题。question 仅回答与追溯，不生成可应用改写。
- 首次发送前说明正文、所选历史和消息会发给 DeepSeek；同意标记仅本机保存。待确认语音/未完成段落先提示完成，不暗中纳入正文。空文和超长文不发请求。
- 所有结果先预览全文与说明，可查看原文；应用时核对 workId、基准 title/body 和未完成编辑。结果过期只保留查看，重新生成需显式点击。应用与恢复都是新的版本；保存失败不标成功、保留候选和导出路径。撤销在当前内容仍等于应用结果时才可直接恢复，否则转到版本预览，绝不抹掉后续手改。
- JSON 导出升级 v2，携带 sessions；导入仍接受 v1。整批校验关联关系后事务创建作品/段落/版本/turn 的新标识，回收站保留会话。刷新后的运行中请求显示已中断，不自动继续计费。恢复/备份包含未完成的候选和聊天，不写入日志。

## Risks / Trade-offs

- 模型可能改错事实 → 明确约束、完整预览和原文对照、版本留存；不能宣传自动事实校验保证。
- 很长会话不能无限放入请求 → 预算内选取并显示覆盖情况，全部本机记录可查，问不清时要求补关键词；不悄悄压缩并丢弃原记录。
- 浏览器清理/空间不足 → 延续本机保存提示与备份补救，保存失败阻止继续请求或假报应用成功。
- 多标签和迟到结果 → 原 revision 事务保护、请求标识、取消状态与正文基准检查；旧响应不能替代新作品。

## Migration Plan

升级只添加 store，不删库、不改写已有正文；保留 v1 备份导入。代码回退前导出 v2 备份，旧程序遇到更高数据库版本须拒绝而非重建。只本地运行，不发布。完成代码检查、构建、桌面浏览器与短文本联调后更新验收并归档；真机 HTTPS 不在本次范围，不以模拟替代。
