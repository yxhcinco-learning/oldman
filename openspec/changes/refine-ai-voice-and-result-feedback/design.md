## Context

会话听写复用 `useSpeechDictation`、`HoldGesture` 与 `SpeechSession`。用户确认同设备的正文语音输入正常，因此 HTTPS、麦克风权限、腾讯云网关和核心识别会话不是本次首要故障面。紧凑听写按钮目前把 `blur`、`lostpointercapture` 与真正松手都交给同一 release；视觉上又只在 `recording` 着色，`permission` / `connecting` 阶段虽然仍在工作却显示为未按下。这些差异只在小文输入区缺少正文语音完整舞台提示时被明显放大。

文章会话把所有 `feedback` 渲染成正文流顶部的常驻条，并在其后单列“查看修改记录”。已应用候选的“查看结果”和“撤销这次优化”使用相同按钮样式；在窄消息气泡中会折成两行，持续挤占对话和输入区。

## Goals / Non-Goals

**Goals:**

- 让网关准备、连接、录音和收尾形成可解释且不会误取消的连续交互。
- 让指针长按与键盘长按各自按真实结束信号收尾，并保留取消、页面隐藏和卸载清理。
- 将普通成功反馈改为不占布局、自动消失的状态提示，持续风险仍保留在内容流中。
- 把修改记录入口纳入页头，把候选操作收成有主次的单行操作组。
- 保持 360–430px 手机宽度、48px 触控目标与现有可访问名称。

**Non-Goals:**

- 不改变腾讯云 ASR 协议、计费调用、识别时长或转写合并规则。
- 不实现点击录音、免按住录音、自动发送或语音聊天。
- 不改变候选状态、事务应用/恢复、文章版本和备份数据。
- 不重做整个文章会话或优化菜单。

## Decisions

### 区分物理按住状态、语音会话状态和输入来源

`useSpeechDictation` 单独维护 `holding` 与当前输入来源。指针 `pointerup` / `pointercancel` 结束指针手势，键盘 `keyup` / 键盘持有期间的 `blur` 结束键盘手势；普通指针 `blur` 和仅表示捕获迁移的 `lostpointercapture` 不再等同于松手。页面隐藏、Escape、卸载仍走取消路径。共享钩子的回归测试同时覆盖正文语音原有停止、取消和阶段稳定性，避免为小文修复引入回退。

按钮在 `holding` 的 permission、connecting、recording 阶段保持按压色；录音前显示“请继续按住”，录音中显示“松开结束”，用户松开进入 finishing 后恢复非按压色并显示“正在确认”。这样视觉反馈表达手指状态，`SpeechSession.phase` 继续表达后台状态，两者不会互相冒充。

### 将普通结果反馈分为短暂通知与持续风险

应用、放弃、成功恢复和复制成功使用约 3 秒自动消失的 dialog 内 toast，状态变更仍由候选元信息永久表达。正文冲突、覆盖风险、复制失败和存储/网络错误继续使用内容流中的持久提示。toast 使用 `role=status`、不抢焦点、不拦截点击。

不把所有反馈都自动隐藏，因为恢复覆盖风险和失败补救需要用户读完并采取行动。

### 页头承担全局入口，消息卡片承担本轮操作

`Dialog` 增加可选页头操作槽。会话页把修改记录放为 48px 图标按钮，保留“查看修改记录”的可访问名称；内容区不再渲染单独一行入口。候选消息内保留一个操作组：“查看…结果”为有背景的主要操作，已应用时追加带撤销图标的弱化“撤销”操作，两者保持同一行并允许在极窄或异常长本地化文字下换行。

页头入口适合全会话级导航，候选操作适合单轮动作；二者不再争夺消息阅读空间。

## Risks / Trade-offs

- [忽略指针导致的普通 blur 可能让异常手势悬挂] → `pointerup`、`pointercancel`、Escape、页面隐藏、pagehide 和卸载继续清理；语音会话仍有时长与连接超时上限。
- [共享手势修改影响正常的正文语音] → 不改变 `SpeechSession`、授权或正文展示，只细分输入来源的结束事件，并用现有正文语音阶段回归锁定节点和控制行为。
- [toast 消失后用户忘记结果] → 候选的“已应用 / 未采用”状态和修改记录永久保留，toast 只承担本次动作确认。
- [页头按钮增加横向密度] → 使用图标、48px 目标和可收缩标题，并在 360、390、430px 与 800px 回归验证无溢出。

## Migration Plan

不涉及数据迁移。先更新共享手势和测试，再更新页头/反馈/候选操作及样式；验证后随普通前端发布替换静态资源。代码回退即可恢复旧交互，IndexedDB、文章版本和服务端协议均无需回滚。
