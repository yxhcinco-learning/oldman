## Context

第一阶段技术已归档，代码与新 AppID 配套已验收；入口仍重复历史状态。H5 演示规格还在活跃规范，旧会话和编辑规则与后续统一规则冲突。.tmp 保存验收脚本及用户备份，不能整体删除。

## Goals / Non-Goals

目标：准确基线、可追溯历史、不冲突的行为规范，以及不受本机临时文件影响的正式检查。
非目标：修改产品交互、部署、停止旧线上服务、清理用户文件或密钥；不启动第二阶段实现，不新增服务或依赖。

## Decisions

1. docs/STATUS.md 作为带日期的接手索引，事实链接最终技术/部署证据；README、OpenSpec context 和协作入口引用它，不重复 AppID 待办。累计 ACCEPTANCE 改为索引，原文移至 archive/phase-one。
2. 退役 isolated-ai-demo / isolated-design-preview 全规格移入 docs/archive/h5/specs，不留空的活跃规格。兼容接口与旧 JSON 仍保留；不能只加免责声明而继续要求保留演示。
3. 完整 Requirement 同步已实现的收起保持访谈、问候不自动记素材、长按语音、当前页编辑、空正文 dialogue、JSON v5；不借清理新增产品行为。
4. root TypeScript/Lint 排除临时输出，正式 scripts 和客户端源码仍检查。依赖扫描跳过生成 npm 包，实际导出由小程序专用构建校验。
5. 增加维护文档相对链接及空 Purpose 检查，仅查本地文件、不联网。回归覆盖临时隔离和退役规格不在活跃目录。

## Risks / Trade-offs

- 历史搬迁可能断链 → 保留旧入口索引，移动文件相对链接改写为原目标，扫描维护文档。
- 误删兼容代码影响线上 → 保留所有协议及鉴权，说明网关/网页分版和回滚差异。
- 文档通过不等于真机重验 → 本轮仅报告本地检查，已有模型/设备证据注明日期，iOS与平台事项独立记录。

## Migration Plan

本地检查配置与文档变更，经 check/build、引用与严格规格校验后本地提交、同步归档。无数据库迁移或发布；回退仅还原本次文件，不碰作品或 Git 历史。

## Open Questions

无阻塞选择。第二阶段由新会话独立建立账号、云作品与同步规格，现有最小身份不是作品所有权系统。
