## Context

网关已有 `OperationLogger`，各 API 只输出 requestId、固定 action、状态、耗时、token 和固定错误类别，Nginx access log 已关闭。这些单条日志安全但不便于编辑实时判断服务状态。H5 的作品、素材和会话继续只在浏览器 IndexedDB；若增加运营事件，必须避免形成用户级行为轨迹。后台当前使用大字号、衬线标题、卡片化窄列和大量留白，截图在 1536px 宽度下仍只给话题列表约 500px，右侧空态占据大半屏，不符合管理工具的信息密度。

## Goals / Non-Goals

**Goals:**

- 采集足够回答“功能有没有被使用、在线请求是否正常”的粗粒度事件，不采集用户是谁或写了什么。
- 在单一管理员后台提供当前进程的实时健康与滚动指标，错误可按固定动作和类别定位。
- 把话题后台调整为中性、紧凑、系统无衬线的标准管理台，并保持桌面与手机关键任务可达。
- 为未来受控部署提供精确代理和限流配置，但不执行服务器变更。

**Non-Goals:**

- 不建设第三方分析、用户画像、跨设备 ID、漏斗到个人、会话回放、广告归因或作品云同步。
- 不收集文章、标题、采访、AI 提示、搜索词、话题/作品 ID、URL、OpenID、IP、User-Agent 或客户端时间。
- 不提供长期历史、外部告警通知、SLA 或跨进程持久监控；重启后的趋势依靠既有脱敏 journald 日志另行分析。
- 不改变用户端 Echoes 视觉，也不部署服务器。

## Decisions

1. **严格事件枚举而非通用属性包。** 客户端只能发送 `{ event }`，事件限于 `app.opened`、`topic.opened`、`writing.started.blank`、`writing.started.topic`、`writing.started.interview`、`backup.exported`、`backup.imported`。Zod strict schema 拒绝额外字段，避免未来无意上传标题、ID 或自由文本。相比允许 `metadata` 再做过滤，结构上禁止更可靠。
2. **尽力而为、零客户端留存。** H5 用同源小请求报告；失败被吞掉，不排队、不写 IndexedDB/localStorage、不重试，也不影响主操作。只在动作成功或明确发生时报告，避免把失败详情从客户端带回。
3. **有界进程内聚合。** `OperationMonitor` 包装现有日志 sink，维护自进程启动以来的有限动作汇总、固定延迟直方图和最近 60 个分钟桶。聚合只含计数、状态分组、token、近似 P95、固定错误类别和服务端时间；不保留 requestId 或原始事件。事件名和内部 action 都限制字符与长度。
4. **管理员监控而非公开指标端点。** `/api/admin/monitoring` 复用现有后台会话 guard，返回配置布尔值、启动时间、运行时长、15/60 分钟和分动作汇总。页面进入时加载并每 30 秒刷新，也提供手动刷新；离开页面清除定时器。公开 `/api/health` 契约保持不变。
5. **双层滥用控制。** 应用事件入口要求精确 Origin、JSON、256B body、严格 schema，并设不按 IP 留存的全局窗口上限；未来 Nginx 精确 location 继续继承 H5 Basic Auth，另按 IP 限流。服务端不把 IP 放进聚合或日志。
6. **后台与用户端分离视觉语言。** 后台使用白色顶栏、浅灰画布、216px 侧栏、系统无衬线、4/8px 间距节奏、6–10px 圆角、边框为主且极弱阴影。桌面话题工作区采用 380px 列表加弹性编辑区；选中后表单与预览并排，空态也落在有边界的工作面板内。760px 以下仍转换为顶部导航和单列。

## Risks / Trade-offs

- [匿名事件仍会让服务器知道某个网络请求发生] → 不记录 IP/User-Agent，不设置标识 Cookie，入口继承受控 H5 认证并只保留聚合；在隐私文档中明确披露。
- [进程内指标重启后丢失] → 页面明确显示“当前进程”，启动时间可见；长期排障继续使用既有脱敏 journald，不将 SQLite 扩展为行为仓库。
- [事件请求增加少量流量] → 只覆盖七个低频关键动作，无自动保存/输入埋点，不重试并加双层限流。
- [后台视觉压缩可能影响窄屏可读性] → 桌面紧凑与手机断点分别定义，手机控件仍至少 44–48px，危险动作文字语义不依赖颜色。
- [监控本身的轮询会计入操作量] → 将 `topic.admin.monitoring` 明确显示为系统监控动作，30 秒刷新上限固定，便于区分业务事件。

## Migration Plan

1. 新增事件枚举、客户端 transport、网关入口和内存聚合；不迁移数据库。
2. 增加受保护监控 API 与后台页面，再重构后台 CSS/结构。
3. 更新 Vite/Nginx 模板、隐私、架构、设计与测试，本地四尺寸验收。
4. 完整检查通过后同步规范并归档；受控服务器保持不变。回滚代码即可移除事件和监控，话题库及浏览器作品不变。

## Open Questions

无。若未来需要跨重启历史或外部通知，必须单独选择保留期、告警渠道和合规边界，不在本变更中预埋第三方服务。
