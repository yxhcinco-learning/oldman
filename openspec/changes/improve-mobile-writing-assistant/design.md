## Context

编辑器采用一个 `100dvh` 的固定画布和上下 flex 布局；桌面模拟尺寸工作正常，但部分移动浏览器在系统键盘弹出时只改变 `visualViewport` 并平移可视窗口，导致布局仍按旧高度计算，顶部或底部工具离开视野。正文语音面板目前固定展开且没有原型中的收起操作。文章优化菜单和会话输入区虽然满足现行功能，但在 640–844px 高度中纵向层级较多，菜单底部入口和键盘后的输入操作不易同屏。

AI 说明由模型自由生成。现有程序只在候选全文与原文完全相同时覆盖说明；只要全文存在任意差异，模型列出的“某句改为同一句（未变）”仍会原样进入会话，因此出现截图中的自相矛盾内容。

## Goals / Non-Goals

**Goals:**

- 在支持 `window.visualViewport` 的移动浏览器中，以实际可见高度和顶部偏移约束应用画布；键盘弹出后页头、正文滚动区和底部文字工具栏仍在同一可视区域。
- 为正文语音面板建立互斥的空闲收起态与待确认“取消 / 完成”态；收起不改输入模式、不触发语音或 AI 请求，正文负责重新唤起。
- 取消普通正文的独立段落编辑页，通过快速双击切到当前页文字输入；语音待确认小窗口的独立编辑保持。
- 在常见手机高度内尽量完整展示文章优化菜单且保持舒适留白，并让会话输入框空值固定单行、真实文字随内容增长、达到上限后自身滚动。
- 通过无额外模型调用的确定性校正，删除修改说明中显式“未变/保持不变”或把同一引文改成自身的条目。
- 让腾讯实时 ASR 模型在服务端可控切换，公网使用 `16k_zh_en` 识别中文、英文和中英混说，并保留无配置时的 `16k_zh` 兼容默认值。
- 保留现有焦点、48px 触控目标、授权、失败补救、候选确认和本机数据边界。

**Non-Goals:**

- 不加入模拟键盘、自定义输入法、自动发送语音、悬浮全局工具栏或新的手势导航。
- 不改变文章 AI 模型、接口、温度、候选正文、IndexedDB/备份结构，也不做第二次计费调用来复核说明。
- 不开放精简、扩写或配图，不把文章优化弹窗改成独立页面。
- 不用桌面尺寸模拟替代 iOS/Android 真机键盘和后台恢复验收。

## Decisions

### 以 Visual Viewport CSS 变量约束应用画布

`ProductApp` 在现有 `.phone-shell` 上监听 `visualViewport.resize` 和 `visualViewport.scroll`，同步实际高度与 `offsetTop` 到 CSS 自定义属性；不支持该 API 时继续使用 `100dvh`。画布仍是一个 flex 容器：页头和工具栏不收缩，正文区承担滚动。选择根画布适配而不是只对输入框执行 `scrollIntoView`，因为后者只能保证焦点可见，不能保证页头与工具栏同时可达，还可能反复触发浏览器自动平移。

### 语音空闲收起与待确认操作互斥

编辑器组件保存内存级 `voiceCollapsed`。默认进入语音模式时展开；只有空闲且没有待确认文字时，麦克风左侧控制位显示收起按钮。产生待确认文字后，收起入口消失，左右控制位改为“取消 / 完成”；取消或完成恢复空闲态后收起按钮重新出现。授权、连接、录音和收尾期间同样不允许收起，避免隐藏关键状态。

收起后不渲染语音舞台或“展开语音输入”条，只保留四项工具栏与正文。正文区域单击恢复语音舞台；快速双击先恢复舞台再切到“文字”页签并聚焦当前页全文输入。点击已选中的“语音”页签也可恢复。收起状态不持久化，不请求麦克风、不改正文。

### 普通正文在当前页编辑

语音预览中的普通段落改为纯文本展示，不再作为进入独立段落编辑页的按钮。用户通过“文字”页签、正文快速双击或触屏长按切换到现有当前页全文 `textarea`，直接调用系统键盘编辑。快速双击使用第二次点击的视口坐标；触屏或触控笔按下约600ms且移动不超过10px时使用按下坐标。两者通过标准 `caretPositionFromPoint` 或 WebKit `caretRangeFromPoint` 回退取得预览 DOM 中的文字偏移，再按段落序号和正文双换行分隔映射到全文的 UTF-16 `selectionStart` / `selectionEnd`；切换后设置相等的起止位置，让折叠光标在点击处闪烁，不选择整段。长按监听不调用 `preventDefault`、不设置 pointer capture，也不拦截 `contextmenu` 或系统选择事件；超过移动阈值、抬起或取消时清除计时，保证滚动仍按浏览器默认行为。源预览在切换后会被 textarea 替换，因此不承诺旧 DOM 的系统选区浮层继续保留，只保证没有主动阻止其触发。点击正文空白或浏览器不提供坐标光标 API 时回退到文末，空正文回退为 0。历史恢复数据若仍包含未完成的普通段落编辑，先把该文字无损合入正文再切到当前页文字模式。

语音待确认小窗口仍可进入独立编辑页，因为其内容尚未并入正文。待确认预览把真实转写单独标记为可定位文字，点击时复用同一坐标光标兼容层取得段内 UTF-16 偏移；独立编辑 textarea 挂载后聚焦并设置相等的 selection，完成后仍返回待确认状态。点击提示、图标或无法命中文字时回退到待确认文字末尾，不把状态提示的长度误算进转写。

标题与正文共享当前页编辑语义。语音模式下聚焦标题时，同步切换 `inputMode` 到文字态、隐藏语音舞台并保留标题本身的焦点，不再调用正文 `textarea.focus()`；正文、待确认语音和恢复数据均不因该切换丢失。全文输入框聚焦时不再绘制额外底部内阴影，避免把装饰线误认为内容分隔线；语音空闲左侧控制组改为单元格内居中，使收起按钮与右侧操作形成视觉平衡。

### 菜单在一屏约束内保留舒适节奏

优化菜单保留“常规优化”主卡、两列四项和小文入口，继续删除重复教学文案，但不把卡片压成工具条。主卡内边距、分区标题上下留白、两列卡片间距与小文入口上方距离恢复为可区分层级的中等节奏；小文入口文案同步缩短，避免换行制造拥挤。短高度设备允许内容滚动，不能为强行一屏而缩小字号或触控目标。目标是在 360×640 的 90dvh 弹窗内仍完整展示，同时比上一版紧凑值更舒展。

### 小文使用消息式自适应编辑条

会话底部改为一行消息编辑条：空值不使用包含提示词的 `scrollHeight`，固定为 52px；提示词缩短为“问小文，或提要求”。只有真实输入值参与高度测量，并增长到约五行，之后自身滚动；语音和“发送”位于同一操作组。小文语音改为点按开始、活动中再次点按取消采集；取消只结束麦克风会话，已显示的识别文字保留在输入框供继续编辑，发送按钮仍须用户点击。选择受控 `textarea` 加高度同步而不是 `contenteditable`，以保留原生输入、长度限制、读屏标签和现有测试语义。

编辑器工具栏第三项“聊天”仅保留未来功能入口，点击后显示短暂的“聊天功能暂未开放”状态提示，不打开现有小文会话、不创建会话或发起 AI 请求。当前小文会话只从“优化”弹窗底部入口进入，避免把两个后续产品方向错误合并。

### 说明校正只移除可确定的伪改动

在共享 `resultSummary` 中按分号、句号和换行拆分说明，移除包含明确“未变/无变化/保持不变/原样保留/无需修改”的条目，以及“将引文 A 改为引文 A”这类两侧规范化后相同的条目；保留其余模型说明。若候选全文有变化但过滤后为空，显示中性的“已完成本轮整理，请对照原文查看具体变化”；全文完全相同仍使用既有固定提示。该校正同时在网关入库前和客户端展示时生效且幂等，不试图用字符 diff 猜测语义级修改。

### 腾讯 ASR 模型只由服务端白名单配置

新增非秘密环境变量 `TENCENT_ASR_ENGINE_MODEL_TYPE`，只接受 `16k_zh` 与 `16k_zh_en`；空值使用兼容默认值 `16k_zh`，其他值在网关启动阶段明确失败，避免拼写错误静默产生错误计费或不可预测识别。网关把选定模型写入腾讯签名参数，浏览器采音、16kHz PCM16、同源 WebSocket、凭据来源和转写合并协议均不改变，也不把模型选择交给客户端。

受控公网运行环境显式设为 `16k_zh_en`，用于中文、英文和中英混说；本地可按需要使用同一变量切换。上线验证包含离线签名契约、服务重启、健康接口和安全的运行日志/单项配置核对；没有合规短音频时不把配置成功冒充真实识别结果，实际中文/英文效果由用户真机试说单列。

## Risks / Trade-offs

- [不同 iOS 版本对 Visual Viewport 的偏移上报存在差异] → 对高度和偏移做有限值/非负校验，保留 `100dvh` 回退，并把真实 iOS/Android 结果单列。
- [语音收起可能与待确认取消混淆] → 两种控制互斥：空闲只显示收起，待确认只显示“取消 / 完成”，活动录音期间不显示收起。
- [正文双击在部分触屏浏览器可能被识别为缩放] → 正文设置 `touch-action: manipulation`，单击恢复语音、双击切文字；显式“文字”页签始终作为等价入口。
- [坐标光标 API 在浏览器间名称不同或点击落在段落空白] → 同时支持标准与 WebKit 接口，只接受预览正文内的命中；无法确定时稳定回退到文末，正文内容不变。
- [长按切换与系统选词/滚动竞争] → 只监听触屏/触控笔且不阻止默认事件；约600ms后额外切换，10px以上移动、抬起或取消均清理计时。切换会替换旧预览，因此系统选区浮层可能随 DOM 消失，真机结果单列，不宣称可同时保留两套 UI。
- [短菜单仍可能因系统字号或极短横屏而滚动] → 优先保持字号和触控目标，允许内部滚动，不以裁切换取一屏。
- [说明过滤无法证明每一句模型说明都与语义差异一致] → 只删除程序可确定的伪改动并提供全文对照；不增加计费调用或声称自动事实保证。
- [自适应高度频繁测量] → 只在输入值或会话页变化时读取当前文本框 `scrollHeight`，上限固定，避免影响消息区滚动。
- [点按语音缺少按住释放的自然结束时机] → 活动态按钮明确表达取消，再次点按立即释放麦克风并保留已显示文字；发送仍保持独立显式操作。
- [`16k_zh_en` 单价可能高于 `16k_zh`，且实际效果受口音和网络影响] → 只在公网显式配置并保留一项变量回切路径；自动化不调用计费服务，真实体验由用户用短语音验证。

## Migration Plan

不涉及数据迁移。先更新规格和契约/组件测试，再实现服务端说明校正、视口适配、语音收起、助手布局及 ASR 模型配置；运行完整检查、构建及四尺寸浏览器回归。ASR 回滚只需把服务端变量改回 `16k_zh` 并重启网关；已有作品、会话、候选及备份不变。

## Open Questions

真实 iOS Safari 与 Android Chrome 的系统键盘、切后台再返回和浏览器工具栏收缩仍需物理设备证据；自动化只验证 Visual Viewport 事件后的布局约束，不冒充真机结果。
