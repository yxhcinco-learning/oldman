## Context

编辑器采用一个 `100dvh` 的固定画布和上下 flex 布局；桌面模拟尺寸工作正常，但部分移动浏览器在系统键盘弹出时只改变 `visualViewport` 并平移可视窗口，导致布局仍按旧高度计算，顶部或底部工具离开视野。正文语音面板目前固定展开且没有原型中的收起操作。文章优化菜单和会话输入区虽然满足现行功能，但在 640–844px 高度中纵向层级较多，菜单底部入口和键盘后的输入操作不易同屏。

AI 说明由模型自由生成。现有程序只在候选全文与原文完全相同时覆盖说明；只要全文存在任意差异，模型列出的“某句改为同一句（未变）”仍会原样进入会话，因此出现截图中的自相矛盾内容。

## Goals / Non-Goals

**Goals:**

- 在支持 `window.visualViewport` 的移动浏览器中，以实际可见高度和顶部偏移约束应用画布；键盘弹出后页头、正文滚动区和底部文字工具栏仍在同一可视区域。
- 为正文语音面板补回明确的收起/展开状态，收起不改输入模式、不清空待确认文字、不触发语音或 AI 请求。
- 在常见手机高度内尽量完整展示文章优化菜单，并让会话输入框从单行起随文字增长、达到上限后自身滚动。
- 通过无额外模型调用的确定性校正，删除修改说明中显式“未变/保持不变”或把同一引文改成自身的条目。
- 保留现有焦点、48px 触控目标、授权、失败补救、候选确认和本机数据边界。

**Non-Goals:**

- 不加入模拟键盘、自定义输入法、自动发送语音、悬浮全局工具栏或新的手势导航。
- 不改变 AI 模型、接口、温度、候选正文、IndexedDB/备份结构，也不做第二次计费调用来复核说明。
- 不开放精简、扩写或配图，不把文章优化弹窗改成独立页面。
- 不用桌面尺寸模拟替代 iOS/Android 真机键盘和后台恢复验收。

## Decisions

### 以 Visual Viewport CSS 变量约束应用画布

`ProductApp` 在现有 `.phone-shell` 上监听 `visualViewport.resize` 和 `visualViewport.scroll`，同步实际高度与 `offsetTop` 到 CSS 自定义属性；不支持该 API 时继续使用 `100dvh`。画布仍是一个 flex 容器：页头和工具栏不收缩，正文区承担滚动。选择根画布适配而不是只对输入框执行 `scrollIntoView`，因为后者只能保证焦点可见，不能保证页头与工具栏同时可达，还可能反复触发浏览器自动平移。

### 语音收起是纯展示状态

编辑器组件保存内存级 `voiceCollapsed`。默认进入语音模式时展开；空闲状态的麦克风控制行左侧提供收起按钮，收起后保留四项工具栏并显示一条 48px 的“展开语音输入”操作，点击已选中的“语音”也可展开。录音、连接或收尾期间不允许收起，避免用户在看不到状态时继续占用麦克风；待确认文字仍通过清空/完成操作处理。选择不持久化该状态，因为它只是本次编辑视图的空间偏好，不应跨文章隐藏语音入口。

### 菜单采用紧凑层级而不缩小文字和触控目标

优化菜单保留“常规优化”主卡、两列四项和小文入口，但减少重复文案、卡片内边距、区块间距及页头空白；图标与标题同行，未开放状态继续直接显示。短高度设备允许内容滚动，不能为强行一屏而把正文降到低于设计规范字号。该方案保持用户已熟悉的信息架构，同时让 360×640 的 90dvh 弹窗在无系统键盘时优先完整显示全部入口。

### 小文使用消息式自适应编辑条

会话底部改为一行消息编辑条：文本框从约一行高度开始，随 `scrollHeight` 自动增长到约五行，之后自身滚动；语音和“发送”位于右侧/底部同一操作组。语音仍是按住手势且只填入文字，发送按钮仍须用户点击。选择受控 `textarea` 加高度同步而不是 `contenteditable`，以保留原生输入、长度限制、读屏标签和现有测试语义。

### 说明校正只移除可确定的伪改动

在共享 `resultSummary` 中按分号、句号和换行拆分说明，移除包含明确“未变/无变化/保持不变/原样保留/无需修改”的条目，以及“将引文 A 改为引文 A”这类两侧规范化后相同的条目；保留其余模型说明。若候选全文有变化但过滤后为空，显示中性的“已完成本轮整理，请对照原文查看具体变化”；全文完全相同仍使用既有固定提示。该校正同时在网关入库前和客户端展示时生效且幂等，不试图用字符 diff 猜测语义级修改。

## Risks / Trade-offs

- [不同 iOS 版本对 Visual Viewport 的偏移上报存在差异] → 对高度和偏移做有限值/非负校验，保留 `100dvh` 回退，并把真实 iOS/Android 结果单列。
- [语音收起可能被误解为取消] → 文案明确为“收起/展开语音输入”，收起不改变状态；活动录音期间禁用收起。
- [短菜单仍可能因系统字号或极短横屏而滚动] → 优先保持字号和触控目标，允许内部滚动，不以裁切换取一屏。
- [说明过滤无法证明每一句模型说明都与语义差异一致] → 只删除程序可确定的伪改动并提供全文对照；不增加计费调用或声称自动事实保证。
- [自适应高度频繁测量] → 只在输入值或会话页变化时读取当前文本框 `scrollHeight`，上限固定，避免影响消息区滚动。

## Migration Plan

不涉及数据迁移。先更新规格和契约/组件测试，再实现服务端说明校正、视口适配、语音收起和助手布局；运行完整检查、构建及四尺寸浏览器回归。回滚仅需恢复组件、样式和说明过滤代码，已有作品、会话、候选及备份不变。

## Open Questions

真实 iOS Safari 与 Android Chrome 的系统键盘、切后台再返回和浏览器工具栏收缩仍需物理设备证据；自动化只验证 Visual Viewport 事件后的布局约束，不冒充真机结果。
